# ADR-001 — Стек и процессы приложения

Статус: proposed
Дата: 2026-09-17

## Контекст

Портал работает на локальном Windows-компьютере для двух инженеров и руководителя, доступ из LAN/VPN (спецификация §1). LocalAI написан на Node.js/Express (`docs/discovery.md` §5.1). Правила рабочего каталога задают стек по умолчанию: React + Vite + TypeScript, Express + TypeScript, PostgreSQL через `pg` без ORM, vitest (`Odintsov/CLAUDE.md`). Спецификация запрещает лишние микросервисы, Kubernetes и второй серверный стек без измеримой необходимости (§3).

Окружение машины разработки на 2026-09-17: Windows 10 Pro 19045, Node.js v24.14.1, npm 11.11, PostgreSQL 18.3 (`psql`, `pg_ctl`), Docker 29.5 (служба остановлена), 16 ГБ ОЗУ, 8 vCPU, 12 ГБ свободно на диске, GPU NVIDIA не обнаружен. Это не целевой ПК с RTX 5050 (U-01).

## Решение

1. **Один серверный стек:** Node.js 24 LTS и TypeScript в строгом режиме для сервера, обработчика заданий и MCP.
2. **HTTP-сервер:** Express. Мажорная версия фиксируется на этапе 02 по актуальной документации.
3. **Интерфейс:** React + Vite + TypeScript, CSS Modules и CSS-переменные. Визуальная система — `BRAND.md` (ветка `design/brand`, предложение).
4. **Данные:** PostgreSQL через `pg` без ORM (ADR-002). Валидация входов и контрактов — одна библиотека схем, общая для API, адаптеров и ответов модели; кандидат — zod, как в LocalAI. Выбор подтверждается на этапе 02.
5. **Тесты:** vitest для unit и integration; сквозные сценарии интерфейса — Playwright с этапа 13.
6. **Процессы — только два процесса приложения плюс PostgreSQL:**

| Процесс | Что делает |
|---|---|
| `server` | HTTP API, раздача собранного интерфейса, MCP-эндпоинт (ADR-010), health/readiness |
| `worker` | задания очереди (ADR-004): импорт, распознавание, выгрузки TenderHub, почта, проверки, генерация файлов, размещение |
| PostgreSQL | транзакционные данные, очередь, аудит |

Файловое хранилище — каталог на диске (ADR-003), не отдельный сервис. Redis, брокеры сообщений и отдельные микросервисы не используются.

7. **Структура репозитория** (npm workspaces):

| Каталог | Содержимое |
|---|---|
| `apps/server` | маршруты API, сессии, MCP-эндпоинт |
| `apps/worker` | цикл заданий и обработчики |
| `apps/web` | интерфейс |
| `packages/core` | доменные правила без ввода-вывода: переходы состояний, матрица блокеров, деньги, канонический JSON |
| `packages/db` | миграции, репозитории с `AccessContext` |
| `packages/adapters` | адаптеры TenderHub, RDWeb, LocalAI, MailHub, переговоров, Яндекс Диска, SMB, модели |
| `packages/contracts` | схемы API, MCP и адаптеров |
| `docs/migrations` | пронумерованные SQL-миграции |

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Python/FastAPI | второй серверный стек рядом с LocalAI на Node; нет выигрыша для задач портала |
| Go | отдельная экосистема, нет переиспользования знаний LocalAI |
| Next.js с SSR | серверный рендеринг в LAN не нужен; усложняет развёртывание на Windows |
| NestJS | избыточный каркас для двух процессов; правила каталога предписывают Express |
| Отдельные сервисы на каждую интеграцию | лишние процессы и сетевые границы без выигрыша (спецификация §3) |

## Последствия

- Совместимость с LocalAI: одна среда выполнения и общие практики; обмен — по HTTP, общий код с LocalAI не делится.
- Windows: Node и PostgreSQL работают нативно, WSL не требуется. Службы и перезапуск — ADR-011.
- MCP: официальный SDK существует для TypeScript (LocalAI уже использует `@modelcontextprotocol/sdk`); версия и транспорт сверяются на этапе 16.
- Ограничение машины разработки (нет GPU, 12 ГБ диска) не позволяет проверить здесь GPU-очередь и большие архивы. Такие проверки планируются на целевом ПК (U-01, U-08).

## Проверка

Этап 02: чистый старт на Windows, `server` и `worker` поднимаются, readiness видит БД, хранилище и heartbeat worker.
