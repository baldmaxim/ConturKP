# ADR-003 — Файловое хранилище оригиналов и выпусков

Статус: accepted (этап 01 принят по `f8a0f20`, `docs/reviews/01-review-4.md`)
Дата: 2026-09-17

## Контекст

Оригиналы документов, экспорты RDWeb, сырые ответы TenderHub, файлы кандидатов и манифесты должны храниться неизменно. Одинаковое содержимое может прийти несколько раз и из разных мест. Удаление из наблюдаемой папки не уничтожает доказательство (I15, A13, A14). Файлы выдаются только по правам, а не по угадываемому пути (этап 12).

## Решение

1. **Адресация по содержимому.** Файл хранится под ключом `sha256/<первые 2 символа>/<следующие 2>/<полный хэш>` в корне хранилища из конфигурации. Метаданные — в таблице `blob`.
2. **Запись без перезаписи:**
   - поток пишется во временный файл в каталоге `tmp/` того же тома;
   - во время записи считается SHA-256 и размер; выполняется `fsync`;
   - если целевой ключ уже существует — сверка размера и хэша, временный файл удаляется (дедупликация);
   - иначе атомарное переименование в целевой ключ, затем вставка `blob`;
   - файл получает атрибут «только чтение».
   Существующий ключ никогда не перезаписывается.
3. **Каталоги корня хранилища:**

| Каталог | Назначение | Резервное копирование |
|---|---|---|
| `sha256/` | оригиналы, экспорты, сырые ответы, файлы кандидатов, манифесты | да |
| `tmp/` | незавершённые записи; очищается при старте от файлов старше суток | нет |
| `derived/` | превью страниц, кэши; пересобираются | нет |

4. **Наблюдаемые папки и входящие** находятся вне корня хранилища. Портал читает их, но не сканирует собственные каталоги (этап 03).
5. **Выдача файлов:** только через API после проверки прав на объект, ссылающийся на `blob` (редакция документа, вложение, файл кандидата). Прямых путей и публичных ссылок нет.
6. **Удаление:** приложение не удаляет `blob`, на которые ссылаются доказательства, кандидаты или выпуски. Политика удержания — после U-07.
7. **Проверка целостности:** периодическое задание пересчитывает хэши выборки файлов и все файлы выпусков перед размещением (A27).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Файлы в PostgreSQL (`bytea`, large objects) | большие PDF (десятки МБ) раздувают БД и резервные копии |
| Имена файлов по исходному имени | коллизии и подмена при одинаковых именах (A13) |
| S3-совместимое хранилище | лишний сервис для одного локального ПК |

## Последствия

- Одинаковое содержимое хранится один раз; происхождения — в `document_occurrence` и `communication_attachment`.
- Резервная копия = дамп БД + каталог `sha256/` + манифест хэшей (ADR-011).
- Защита от администратора ОС не абсолютна (I19).

## Проверка

Этап 03: повторное обнаружение, одинаковое имя с другим содержимым, переименование, сбой во время записи (во временном каталоге остаётся мусор, `blob` не создаётся), выдача файла без прав — отказ.
