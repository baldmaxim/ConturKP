# ADR-005 — Деньги, время, оптимистичная конкуренция и идемпотентность

Статус: proposed
Дата: 2026-09-17

## Контекст

Деньги считаются программно в decimal по семантике TenderHub; валюта, единица, НДС, дата и вид цены входят в сопоставление (I10). TenderHub считает строки в `float64`, а `cached_grand_total` — в decimal с округлением до копеек (`docs/discovery.md` §4.2). Валюты портала — рубли, USD, EUR, CNY (D-004). Два одновременных изменения не должны перезаписывать друг друга молча (I13, A24). Повторы операций не должны создавать дублей (I14).

## Решение

### Деньги и количества

1. **Хранение:** `numeric` без округления при записи. Для значений, пришедших из внешнего JSON и участвующих в сверке, дополнительно хранится исходная лексема числа (`raw_lexemes`).
2. **Разбор JSON TenderHub:** числа читаются из текста ответа без промежуточного `float`. Способ (доступ к исходному тексту числа при разборе или потоковый парсер) выбирается на этапе 06 по актуальной документации Node.js и проверяется тестом на значениях с 15+ значащими цифрами.
3. **Арифметика на сервере:** только одна библиотека десятичной арифметики произвольной точности; кандидат — decimal.js, выбор подтверждается на этапе 10. JavaScript `number` для денег и количеств запрещён.
4. **API:** суммы передаются объектом:

```json
{ "amount": "1234567.80", "currency": "RUB", "vat": "included", "priceKind": "commercial", "unit": "м3", "asOf": "2026-09-17", "source": { "type": "calculation_line", "id": "…" } }
```

   `amount` — десятичная строка; `currency` ∈ `RUB`, `USD`, `EUR`, `CNY`, `UNKNOWN`; `vat` ∈ `included`, `excluded`, `not_applicable`, `unknown`; `priceKind` ∈ `cost`, `supplier_quote`, `commercial`, `unknown`.
5. **Сопоставимость:** два значения сравниваются, только если совпадают валюта, признак НДС, вид цены и база единицы (после явного пересчёта объёма). Иначе результат `incomparable` с причиной, а не замечание о расхождении (A18, A19, A21).
6. **Пересчёт валют:** только по курсу из ревизии расчёта (`fx_rates` с датой); курс и его источник сохраняются в результате.
7. **Округление:** только в явных шагах с именованной политикой. Для итога КП TenderHub — десятичное округление до 2 знаков «от нуля» (как `cached_grand_total`). Допуски сверки задаются по полю и записываются в результат. Разница округления показывается отдельной строкой, а не подгонкой.

### Время

8. Все моменты — `timestamptz`, хранение в UTC; API — ISO 8601 с `Z`. Бизнес-даты без времени — `date`. Отображение — часовой пояс из настройки, по умолчанию `Europe/Moscow` (спецификация §12). Сервер не опирается на часовой пояс ОС.

### Оптимистичная конкуренция

9. Изменяемые агрегаты несут `row_version bigint`. `GET` возвращает `ETag: "<id>:<row_version>"`. Изменяющие команды требуют `If-Match`: без него — `428`, при несовпадении — `412` с текущим состоянием. Last-write-wins не используется (A24).
9a. `row_version` защищает одну строку, но не ловит появление новых строк (новый источник, новое решение). Для этого у этапа есть барьер актуальности: монотонный `tender_stage.input_version`, события `stage_input_event` и единый порядок блокировок. Согласование, выпуск и регистрация отправки проверяют его под блокировкой строки этапа (`docs/architecture/state-machines.md` §1.1–1.2, R01-03). Актуальность кандидата подтверждается составом его входов: событие источника покрыто, только если его содержимое учтено снимком области кандидата; номер версии снимка или момент сборки актуальность не подтверждают.

### Идемпотентность

10. **Команды API**, создающие записи или запускающие внешние действия, принимают `Idempotency-Key` (UUID клиента). Запись `idempotency_record` (`principal_id`, `key`, `request_hash`, ответ) делается в транзакции команды. Повтор с тем же ключом и тем же телом возвращает сохранённый ответ; тот же ключ с другим телом — `422 IDEMPOTENCY_KEY_REUSED`. Срок хранения записей — не меньше 7 дней.
11. **Задания** — `dedupe_key` (ADR-004) и уникальные ключи результата: `document_revision` (`document_id`, `blob_sha256`); `release` (`candidate_id`); `delivery` (`release_id`, `destination_id`); `model_suggestion` (`created_by_principal`, `request_id`); `send_event` (`registered_by`, `idempotency_key`).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Суммы в копейках целыми | не покрывает количества, коэффициенты и цены с точностью больше 2 знаков |
| `float` / JavaScript `number` | нарушает I10; ошибки округления в сверке |
| Last-write-wins с журналом | молчаливая потеря правки (A24) |
| Идемпотентность только на клиенте | не защищает от повтора после сетевого сбоя |

## Последствия

- Все сравнения цен проходят через функцию сопоставимости в `packages/core`; прямое сравнение чисел в коде запрещено ревью.
- Неизвестная валюта или НДС дают `incomparable`, а не ложное замечание.
- Клиент интерфейса хранит `ETag` и ключ идемпотентности до ответа сервера.

## Проверка

Этап 02: `412` при устаревшем `If-Match`. Этап 10: decimal и округления, валюты, НДС, единица против итога, повторный импорт даёт тот же результат.

## Связанные требования

I10, I11, I13, I14; A18–A24, A26, A29, A37.
