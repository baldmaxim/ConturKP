# ADR-008 — Область поиска: явные ID разрешённых единиц источника

Статус: accepted (этап 01 принят по `f8a0f20`, `docs/reviews/01-review-4.md`)
Дата: 2026-09-17 (исправлено по ревью 01-1: R01-01, R01-02)

## Контекст

Поиск ограничен тендером, правами и выбранным набором источников; поздний документ не появляется в режиме исторического выпуска (I05, A11, A12). Нельзя искать по всему текущему индексу и потом фильтровать top-k (спецификация §3). LocalAI фильтрует только по источнику до ранжирования, строит ID фрагмента из пути и номера чанка и расширяет поиск по договору на связанные тендеры (`docs/discovery.md` §5). Второй OCR/RAG без доказанной необходимости создавать нельзя (C01). «Не найдено» не равно «не предусмотрено» (I07).

Ревью 01-1 показало: фильтр по редакциям документов недостаточен. У одного PDF может быть несколько прогонов распознавания (R1, R2), а письма и транскрипции — отдельные сущности. Область должна называть конкретные единицы источника и совпадать с входами проверки.

## Решение

1. **Единица источника** — то, из чего получены фрагменты: прогон распознавания (`recognition_run`), письмо (`communication`), редакция транскрипции (`transcript_revision`). У каждого фрагмента записаны `source_unit_type` и `source_unit_id`.
2. **Снимок области** — неизменяемый `evidence_scope` с типизированными элементами: редакция документа + выбранный прогон, письмо, редакция транскрипции (`docs/architecture/state-machines.md` §5.1). Проверка, кандидат, манифест, исторический поиск и MCP по выпуску используют один и тот же снимок.
3. **`SearchScope` строит сервер:**

| Поле | Откуда |
|---|---|
| `tenderId` | запрос; проверяется `AccessContext` |
| `mode` | `working` (текущий черновой состав), `review` (снимок проверки), `release` (снимок выпуска), `comparison` (два снимка) |
| `evidenceScopeId` | для `review`, `release`, `comparison` — сохранённый снимок; для `working` — временный снимок из `draft`-ревизии набора и последних прогонов, его хэш пишется в результат |
| `allowedSourceUnits` | единицы снимка минус письма из ящиков, недоступных пользователю сейчас |
| `scopeHash` | хэш снимка + хэш применённого фильтра прав; пишется в результат и аудит |

   Клиент не передаёт ID единиц сам: он выбирает этап, проверку или выпуск, сервер разворачивает область.
4. **Права поверх снимка.** Снимок не даёт вечного разрешения: доступ к ящикам проверяется при каждом запросе, письма без доступа исключаются из `allowedSourceUnits` до ранжирования (A35).
5. **Фильтр до ранжирования.** Любой поиск — портальный или LocalAI — отбирает кандидатов только среди фрагментов с `source_unit_id ∈ allowedSourceUnits`. Постфильтрация результатов top-k запрещена.
6. **Исторический режим** использует только снимок выпуска. Более поздние прогоны того же PDF, новые письма и редакции транскрипций в область не входят (A10, A11).
7. **Точный и полнотекстовый поиск — в PostgreSQL портала** по неизменяемым `evidence_fragment`: точные обозначения (коды листов, марки, номера позиций) и полнотекстовый поиск с конфигурацией `russian`. Это не второй RAG: нет OCR, эмбеддингов и генерации. Это поиск по собственному реестру доказательств, который нужен для полноты прохода (спецификация §12), изоляции и стабильных цитат. Необходимость обоснована отсутствием фильтра по редакциям и стабильных ID в LocalAI (`docs/discovery.md` §5.2).
8. **Смысловой поиск — LocalAI** после X-04 по контракту `docs/contracts/adapters.md` §4: индексируются фрагменты с ID портала и единицей источника; поиск принимает `allowedSourceUnitIds` и фильтрует до top-k; ответ ссылается на ID фрагментов портала. Адаптер проверяет каждый возвращённый фрагмент по той же полной области; ответ с фрагментом вне области отклоняется целиком и пишется в аудит.
9. **До X-04** смысловой поиск недоступен: ответ поиска содержит `semantic: "unavailable"` и причину. Точный и полнотекстовый поиск работают. Тихого переключения на поиск по всему индексу LocalAI нет (A42).
10. `linkedContractId` LocalAI не используется для построения области: договор входит в область, только если его единица есть в снимке.
11. **Результат поиска** содержит область (`scopeHash`, число единиц по типам), признаки неполноты (неполное распознавание, недоступный смысловой поиск, исключённые по правам единицы — без их содержимого) и формулировку пустого результата: «не найдено в области: N единиц, M страниц распознано из K». Пустой результат не превращается в «не предусмотрено» (I07).
12. **Цитата** — ссылка на `evidence_fragment.id` + страница и координаты. Превью открывает локальный оригинал и выделяет фрагмент; внешний crop URL не нужен и не загружается (A17, A38).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Фильтр только по редакциям документов | пропускает поздний прогон того же PDF и не выражает письма и транскрипции (ревью 01-1, R01-02) |
| Список разрешённых ID фрагментов в каждом запросе | корректно, но списки в десятки тысяч ID на каждый запрос; единицы источника компактнее и дают тот же результат |
| Поиск по всему индексу LocalAI с фильтром результатов | запрещено спецификацией; теряет релевантные результаты и может раскрыть счётчики |
| Собственный векторный индекс портала | второй RAG (C01) без доказанной необходимости |
| Отдельный индекс LocalAI на каждый выпуск | дублирование индекса, пересборка при каждом выпуске; допустимо как реализация X-04 на стороне LocalAI |

## Последствия

- Портал хранит тексты фрагментов в PostgreSQL и индексирует их полнотекстово; это производный индекс (`fragment_index_state`), пересобираемый без потери доказательств.
- X-04 расширен: LocalAI должен принимать единицу источника при индексации и фильтр `allowedSourceUnitIds` при поиске (`docs/architecture/unknowns.md`).
- Приёмка этапа 05 со смысловым поиском зависит от X-04; без него этап 05 принимается только для точного и полнотекстового поиска с явной пометкой.
- Если владелец LocalAI отклонит X-04 (Q-13), решение пересматривается отдельным ADR; доменная модель и контракт `SearchScope` не меняются.

## Проверка

Этап 05: два тендера с одинаковой фразой; два этапа с противоположными ответами; два прогона одного PDF, где поздний ранжируется выше при `limit = 1`; письмо из недоступного ящика на первом месте по релевантности; переиндексация не ломает старую цитату; удаление индекса не уничтожает оригинал; пустой результат не утверждает отсутствие требования (A10–A12, A35, A42, A44). Бумажные сценарии — `docs/architecture/walkthroughs.md` §6 и §11.
