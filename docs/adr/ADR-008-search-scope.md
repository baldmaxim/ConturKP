# ADR-008 — Область поиска: явные ID разрешённых редакций

Статус: proposed
Дата: 2026-09-17

## Контекст

Поиск ограничен тендером, правами и выбранным набором источников; поздний документ не появляется в режиме исторического выпуска (I05, A11, A12). Нельзя искать по всему текущему индексу и потом фильтровать top-k (спецификация §3). LocalAI фильтрует только по источнику до ранжирования, строит ID фрагмента из пути и номера чанка и расширяет поиск по договору на связанные тендеры (`docs/discovery.md` §5). Второй OCR/RAG без доказанной необходимости создавать нельзя (C01). «Не найдено» не равно «не предусмотрено» (I07).

## Решение

1. **Область поиска — объект `SearchScope`, который строит сервер:**

| Поле | Откуда |
|---|---|
| `tenderId` | запрос; проверяется `AccessContext` |
| `mode` | `working` (текущий черновой набор), `release` (выпуск), `comparison` (два выпуска) |
| `documentRevisionIds` | из `source_set_revision` этапа или выпуска; для `comparison` — два списка раздельно |
| `recognitionRunIds` | действующие прогоны для этих редакций в момент фиксации области |
| `mailboxFilter` | доступные пользователю ящики |
| `scopeHash` | хэш отсортированных ID; пишется в результат и аудит |

   Клиент не передаёт ID редакций сам: он выбирает этап или выпуск, сервер разворачивает область.
2. **Фильтр до ранжирования.** Любой поиск получает `documentRevisionIds` и `recognitionRunIds` и применяет их до выбора кандидатов. Постфильтрация результатов top-k запрещена.
3. **Исторический режим** использует только замороженную `source_set_revision` выпуска и прогоны распознавания, закреплённые в его манифесте. Более поздние редакции и прогоны в область не входят (A11).
4. **Точный и полнотекстовый поиск — в PostgreSQL портала** по неизменяемым `evidence_fragment`: точные обозначения (коды листов, марки, номера позиций) и полнотекстовый поиск с конфигурацией `russian`. Это не второй RAG: нет OCR, эмбеддингов и генерации. Это поиск по собственному реестру доказательств, который нужен для полноты прохода (спецификация §12), изоляции и стабильных цитат. Обоснование необходимости — отсутствие фильтра по редакциям и стабильных ID в LocalAI (`docs/discovery.md` §5.2).
5. **Смысловой поиск — LocalAI** после X-04: портал передаёт фрагменты с ID портала и ID редакций; поиск принимает список разрешённых редакций и фильтрует до top-k; ответ ссылается на ID фрагментов портала. Ответ со ссылкой на фрагмент вне области отклоняется адаптером и пишется в аудит.
6. **До X-04** смысловой поиск недоступен: ответ поиска содержит `semantic: "unavailable"` и причину. Точный и полнотекстовый поиск работают. Тихого переключения на поиск по всему индексу LocalAI нет (A42).
7. `linkedContractId` LocalAI не используется для построения области: договор входит в область, только если его редакция есть в наборе источников этапа.
8. **Результат поиска** всегда содержит область (`scopeHash`, число редакций), признаки неполноты (неполное распознавание, недоступный смысловой поиск) и формулировку пустого результата: «не найдено в области: N редакций, M страниц распознано из K». Пустой результат не превращается в «не предусмотрено» (I07).
9. **Цитата** — ссылка на `evidence_fragment.id` + страница и координаты. Превью открывает локальный оригинал и выделяет фрагмент; внешний crop URL не нужен и не загружается (A17, A38).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Поиск по всему индексу LocalAI с фильтром результатов | запрещено спецификацией; теряет релевантные результаты и может раскрыть счётчики |
| Собственный векторный индекс портала | второй RAG (C01) без доказанной необходимости |
| Отдельный индекс LocalAI на каждый выпуск | дублирование индекса, пересборка при каждом выпуске; можно рассмотреть как вариант X-04 на стороне LocalAI |
| Только LocalAI для всего поиска | до X-04 изоляция и стабильные цитаты недостижимы; этап 05 не будет принят |

## Последствия

- Портал хранит тексты фрагментов в PostgreSQL и индексирует их полнотекстово; это производный индекс (`fragment_index_state`), пересобираемый без потери доказательств.
- Приёмка этапа 05 со смысловым поиском зависит от X-04; без него этап 05 принимается только для точного и полнотекстового поиска с явной пометкой.
- Если владелец LocalAI отклонит X-04 (Q-13), решение пересматривается отдельным ADR; доменная модель и контракт `SearchScope` не меняются.

## Проверка

Этап 05: два тендера с одинаковой фразой, два этапа с противоположными ответами, перепривязка договора, переиндексация не ломает старую цитату, удаление индекса не уничтожает оригинал, пустой результат не утверждает отсутствие требования (A10–A12, A42, A44).

## Связанные требования
