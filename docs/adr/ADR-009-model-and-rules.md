# ADR-009 — Место модели и программных правил

Статус: proposed
Дата: 2026-09-17

## Контекст

Модель не калькулятор (I10) и не имеет полномочий (I12). Гипотеза без основания не становится фактом (этап 08). Команды внутри документов — недоверенные данные (I16). Предположение модели о причине изменения подтверждает человек (I11). Внешняя обработка разрешена владельцем, но системы и объём передаваемых данных задаются настройками (спецификация §1). Подписка Codex/Cursor не является backend API (спецификация §11).

## Решение

### Разделение обязанностей

| Задача | Кто выполняет | Результат |
|---|---|---|
| Переходы состояний, права, блокеры, неизменяемость | программные правила сервера (`packages/core`) | факт |
| Деньги, объёмы, сопоставимость, разложение изменения цены | программные правила | факт с методикой |
| Комплектность, единицы, арифметика, явные табличные объёмы, дубли | программные правила | результат проверки (`review_check_result`) |
| Извлечение кандидатов требований, гипотезы разногласий, причины изменений, черновики полей и вопросов, описание изображений | модель | `model_suggestion` со ссылками на фрагменты |
| Принятие гипотезы, решение, закрытие замечания, принятие риска, согласование, выпуск, отправка | человек | `decision`, переходы с автором-человеком |

### Шлюз модели

1. Все обращения к модели — через интерфейс `ModelGateway` в `packages/adapters`. Вход: вид задачи, версия промпта, список фрагментов-доказательств с ID из текущей области (ADR-008), JSON-схема ответа. Выход: JSON.
2. **Валидация до записи:** ответ проходит схему; каждый `cited_fragment_id` существует и входит в область; числа из ответа модели в деньги не превращаются. Невалидный ответ — отказ с записью причины, без частичного сохранения.
3. **Изоляция инструкций (I16):** системные инструкции задаются сервером; текст документов передаётся как данные в отдельных блоках с явной разметкой. У модели нет инструментов, меняющих состояние.
4. **Воспроизводимость входов:** в `model_suggestion` и `review_run` пишутся модель, версия, `prompt_hash`, `input_scope_hash`, настройки. Побитовая воспроизводимость ответа не обещается (05, «Оценка модели» п. 4).
5. **Провайдеры:** по умолчанию локальный (LM Studio или локальная модель LocalAI; точный API сверяется на этапе 08). Внешний провайдер включается настройкой с указанием системы и классов данных, которые разрешено передавать. Автоматического облачного fallback нет.
6. **Ограничение GPU:** обращения к локальной модели — задания класса `gpu` (ADR-004).
7. **Отказ модели** (таймаут, пустой ответ, невалидный JSON) даёт видимый статус проверки `incomplete`, а не «проверено» (I18).

### Чат через Codex и Cursor

8. Внешние чат-клиенты работают через MCP портала (ADR-010) в правах пользователя. Их ответы в чате — рабочее обсуждение. В портал они могут записать только предложения (`model_suggestion`), которые принимает человек.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Модель как калькулятор сумм | нарушает I10 |
| Автоматическое принятие гипотез с высокой уверенностью | нарушает I11, I12 |
| Встроенный облачный чат в портале | не обязательный объём; подписочные токены не backend API (спецификация §11, C03) |
| LocalAI переписывает найденные основания перед передачей | запрещено спецификацией §2 |

## Последствия

- Любой вывод в интерфейсе различает факт правила, гипотезу модели и решение человека (I06, BRAND.md §4.5, ветка `design/brand`).
- Оценка качества модели ведётся отдельно от правил (05, «Оценка модели»).

## Проверка

Этапы 08–09: ложная цитата модели отклоняется, отказ модели даёт `incomplete`, инструкция «игнорируй правила» в документе не меняет поведение (A36), повтор извлечения не дублирует гипотезы.

## Связанные требования
