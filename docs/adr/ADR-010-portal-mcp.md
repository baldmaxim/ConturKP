# ADR-010 — MCP-сервер портала для Codex и Cursor

Статус: accepted (этап 01 принят по `f8a0f20`, `docs/reviews/01-review-4.md`)
Дата: 2026-09-17

## Контекст

Codex и Cursor — интерактивные клиенты общего MCP (спецификация §11, 02 п. 10). MCP по умолчанию только читает; контролируемые записи — только предложения. Контекст запроса явный и передаётся в каждый инструмент; при неоднозначном тендере инструмент возвращает выбор без лишних данных. Инструменты LocalAI MCP только читают и не знают области тендера (`docs/discovery.md` §5.1).

## Решение

1. **Один MCP-сервер портала** внутри процесса `server` (ADR-001). Транспорт — сетевой транспорт MCP по HTTPS, потому что клиенты работают на ПК инженеров, а портал — на отдельном компьютере. Конкретная версия спецификации MCP, SDK и транспорта сверяется с официальной документацией на этапе 16.
2. **Аутентификация:** персональный `api_token` пользователя (ADR-006) с областями `read` и `propose`. Токен выпускает сам пользователь в портале, показывается один раз, хранится хэшем, отзывается. Действия MCP пишутся в аудит с `principal_kind = model_via_mcp` и `on_behalf_of_user_id`.
3. **Явная область в каждом вызове:** `tenderId` и `stageId` или `releaseId`; для сравнения — `leftReleaseId` и `rightReleaseId`. Сервер разворачивает область по ADR-008. Без области инструмент возвращает список доступных пользователю тендеров и этапов (коды и названия), без данных тендеров.
4. **Инструменты** — `docs/contracts/mcp-tools.md`. Чтение: выбор дела, документы и цитаты, поиск, смета и экономика, вопросы и решения, готовность, сравнение. Запись — только `propose_*` с обязательным `requestId`.
5. **Запрещено:** approve, release, send, resolve hold, accept risk, изменения пользователей и настроек, произвольный SQL, shell, файловая система, скачивание файлов по пути (C03, I12).
6. **Ограничения ответа:** пагинация, лимит размера, суммы — десятичные строки с валютой, НДС и видом цены, ссылки на фрагменты — стабильные ID портала.
7. **Защита от инструкций в данных (I16):** текст документов возвращается как данные; сервер не выполняет команд из текста и не расширяет область по содержанию документа.
8. **Секреты** не попадают в результаты: ответы проходят редактирование известных шаблонов секретов и внутренних URL (I17).
9. **Идемпотентность:** повтор `propose_*` с тем же `requestId` возвращает ту же запись (A37).

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Расширить MCP LocalAI | LocalAI не знает тендеров, прав и выпусков; область и права — ответственность портала |
| stdio MCP на ПК пользователя с прямым доступом к БД | обходит серверные права и аудит |
| Встроенный чат на подписке Codex/Cursor | запрещено (C03) |
| MCP с правом согласования «по подтверждению в чате» | нарушает I12 |

## Последствия

- Тексты цитат, выдаваемые MCP, проходят те же проверки области, что и интерфейс.
- Настройка клиентов Codex и Cursor документируется на этапе 16 по их актуальной документации; прочитанный пример конфигурации не считается подключением.

## Проверка

Этап 16: неоднозначный тендер, исторический вопрос, чужой тендер, несуществующая цитата, инструкция в PDF, повтор `requestId`, отсутствие секретов в ответах; live-gate для каждого клиента отдельно (F15, F16).

## Связанные требования

I05, I12, I13, I16, I17; A11, A12, A25, A36, A37; C03; F15, F16.
