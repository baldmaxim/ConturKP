# ADR-013 — Формирование файлов выпуска: форматы, разметка образцов, превью

Статус: accepted (решения владельца D-032, `docs/reviews/12-owner-decisions.md`; этап 12)
Дата: 2026-10-06

## Контекст

Этап 12 формирует комплект-кандидат из файлов по образцам компании. Задание требует зафиксировать точный набор форматов в ADR и показывать превью именно того файла, который будет согласован. Образцы компании (Q-08, проект этапа 11 §1a, проект этапа 12 §1a) — DOCX (письмо КП, методики) и XLSX («Существенные условия», «Компенсация», расчёт содержания площадки); неизменяемые вложения — DOCX и DOC. Переменные части письма выделены цветом, в методиках — пропуски «____». До этапа 12 в портале не было ни записи DOCX/XLSX, ни конвертера в PDF; выдача офисных файлов — только скачиванием (ADR-003), просмотр — pdf.js на canvas.

Набор форматов для заказчика и способ превью — бизнес-решения владельца (D-032 В-12-1, В-12-2); выбор библиотек — технический.

## Решение

1. **Форматы.**
   - Заказчику: сгенерированные документы в формате размеченного образца — DOCX или XLSX; стандартные вложения «как есть» — DOCX, DOC, XLSX, PDF.
   - Внутренние: PDF-превью каждого файла комплекта (получено конвертацией именно этого файла, связано с ним SHA-256), манифест.
   - Других форматов генерации нет: образец ревизии иного формата — отказ с причиной.
2. **Разметка образца** (В-12-3). Оригинал образца ревизии сохраняется; разметка делается в отдельной копии (размеченный образец ревизии). Плейсхолдеры:
   - `{{ключ}}` — значение поля схемы `forms/1` той же ревизии;
   - `{{#ключ}}…{{/ключ}}` — блок только для применимого поля; для поля-таблицы — повторение строки или абзаца для каждой строки, внутри блока `{{колонка}}` — ячейка строки;
   - разметка проверяется ядром до утверждения ревизии: каждый ключ есть в схеме и подходит по типу, каждое обязательное поле выводится, у таблицы — колонки, блоки закрыты и вложены верно; итог хранится в ревизии и неизменен вместе с ней.
3. **Генерация.**
   - DOCX — `docxtemplater` (MIT) поверх `pizzip`: плейсхолдеры, разорванные Word на несколько фрагментов текста, блоки и повторения; остальное содержимое пакета не меняется.
   - XLSX — собственная замена текста ячеек (`sharedStrings`, `inlineStr`) в пакете образца тем же `pizzip`: книга не пересохраняется сторонним движком — сохраняются область печати, объединения, стили, формулы. Ячейка, целиком занятая плейсхолдером числового поля, получает число.
   - Значение — данные, а не разметка (I16): фигурные скобки значения не образуют плейсхолдеров.
   - ZIP пишется детерминированно (порядок и даты записей образца): одинаковые входы — одинаковые байты.
   - Тестовый режим и демо-шаблон — видимая отметка в документе (DOCX — первый абзац; XLSX — первая строка листа), а значит и в превью (В-12-8).
4. **Превью и конвертер** (В-12-2).
   - LibreOffice без интерфейса: `soffice --headless --convert-to pdf` в отдельном процессе worker, с отдельным профилем, ограничением времени и без сети. Путь — настройка `SOFFICE_PATH` (иначе — поиск `soffice` в `PATH` и в стандартном каталоге установки Windows).
   - Версия конвертера (`soffice --version`) и шрифты, встроенные в каждый PDF, записываются в комплект и манифест.
   - Подмена шрифтов: шрифт, которым набран текст документа, обязан быть встроен в PDF; иначе сборка не проходит (`font_substituted`). Отсутствие конвертера (`converter_unavailable`) и ошибка преобразования (`conversion_failed`) — тоже провал сборки.
   - Проверки отрисовки и снимки страниц — pdf.js с `@napi-rs/canvas`; снимки — для просмотра человеком (В-12-10).
5. **Выдача.** Файлы, PDF, снимки страниц и ZIP комплекта — только через API по ID после проверки прав на кандидата при каждом запросе (В-12-7; ADR-003 п. 5).

## Последствия

- На сервере (целевой ПК, ADR-011) и на машине разработки и ревью устанавливается LibreOffice и шрифты образцов; без них комплект не собирается — это видно, а не скрыто. Проверка установки — этап 17 (U-08).
- Отрисовка LibreOffice близка к Word, но не тождественна; поэтому автоматические проверки PDF дополняются просмотром страниц человеком, а реальные формы принимаются вместе со снятием Q-08.
- Новые зависимости: `docxtemplater`, `pizzip`.

## Реализация (этап 12)

Уточнения без изменения решения:
- Код: ядро `packages/core/src/release/` (разметка, вывод значений, сверка с расчётом, манифест, отметки); адаптер `packages/adapters/src/office/` (OOXML, генерация, шрифты, разбор PDF, контракт конвертера); конвертер LibreOffice — в worker (`apps/worker/src/office/libreoffice.ts`): пакет адаптеров не работает с файлами и процессами (A38, `tests/adapters.test.ts`).
- DOCX: `docxtemplater` со своим разборщиком тегов. Неприменимое поле в простом теге даёт пустую строку, в блоке — скрывает блок. Абзац вне таблицы, целиком занятый одним блоком, удаляется вместе со скрытым блоком: иначе остаются пустые строки, а у автоматического списка — номер без текста (S12-03). В размеченной копии условные пункты списка нумеруются автоматическим списком Word; ручные номера при скрытом пункте дают пропуск.
- Денежное поле (с валютой и `scale`) печатается с `scale` знаками после запятой («120,00»); значение не округляется. Число в ячейке XLSX — каноническая запись, знаки показывает формат ячейки образца.
- Отметки режима: DOCX — отдельными абзацами в начале тела документа. XLSX — в верхнем колонтитуле печати каждого листа и в начале первой текстовой ячейки.
- «Без сети» (S12-04): у конвертации временный профиль. В нём заблокирована загрузка внешних ресурсов документа (`BlockUntrustedRefererLinks`) и запрещено выполнение макросов (`DisableMacrosExecution`, `MacroSecurityLevel` = 3). До исправления LibreOffice загружал картинку по внешней ссылке из DOCX. Регрессия проверяет картинку по ссылке, поле `INCLUDEPICTURE` и формулу `WEBSERVICE`: запросов нет. Сетевой изоляции на уровне ОС нет.
- Снимки страниц (PNG) портал по API не выдаёт: превью — PDF, браузер рисует его на canvas. PNG для просмотра человеком делают проверочные скрипты: `artifacts/stage-12/page-review.mjs` и `ui-check.mjs` с `UI_SHOTS`.
- Windows (R12-01, Review 12-1): вход — консольный `soffice.com`. Через оконный `soffice.exe` определение версии не завершалось (на LibreOffice 26.8.0.3 — тайм-аут 120 с, через `soffice.com` — около 2,5 с). Поиск предпочитает `soffice.com` в `PATH` и в стандартном каталоге; настроенный `soffice.exe` заменяется соседним `soffice.com`, если тот есть.
- Установка — `docs/runbooks/libreoffice.md`; настройки — `SOFFICE_PATH`, `OFFICE_CONVERT_TIMEOUT_SECONDS`; путь для тестов — `KONTUR_TEST_SOFFICE`.
