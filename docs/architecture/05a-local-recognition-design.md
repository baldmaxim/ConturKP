# Этап 05a — проект миграции 0014 и локального распознавания

Документ составлен до миграции по порядку работы решения владельца (`docs/reviews/05a-owner-decisions.md`, D-024): сначала проект миграции для AD-05a-1 и AD-05a-3, затем реализация. Раздел 8 — проверка условия остановки: не требуется ли фундаментально менять принятые инварианты этапов 04 и 05.

## 1. Что решено владельцем и что уточняет этот проект

## 3. Выбор предпочтительного прогона (AD-05a-3)

`recognition_preferred_run(p_revision)` — детерминированная функция:

1. успешные прогоны редакции — `complete` или `partial`;
2. класс движка: `rdweb_export` и `rdweb_api` выше `local_ocr` (и `text_layer`, который не используется);
3. внутри класса — глубина в линейной цепочке `supersedes_run_id` (рекурсивный обход от корня), глубже — новее по истории.

Время создания, номер задания и порядок worker в правиле не участвуют. Ручного переопределения нет: спецификация его не предусматривает (решение владельца, AD-05a-3).

Функцию используют: автоподбор снимка и текущей области этапа (`setRevisionItemsWithRuns`), область договора (`resolveContractScope`), охранник снимка, охранник прогона поиска и отметка «используется» в списке прогонов. Для данных до 05a (только RDWeb) результат совпадает с прежним «хвостом цепочки».

Гонка «область вычислена → прогон завершился → вставка прогона поиска» даёт отказ охранника; API возвращает `409 STATE_CONFLICT` с причиной `scope_changed`, как при изменении прав.

## 4. Маршрут и правила локального прогона (OD-1, OD-2, OD-4, D-014)

`recognition_revision_route(p_revision)`:

| Тип файла редакции (`blob.media_type`) | Маршрут |
|---|---|
| `.docx`, `.xlsx`, `.csv` | `local` — RDWeb нормативно не используется |
| PDF, у редакции есть прогон RDWeb в `queued`, `running`, `complete` или `partial` | `rdweb` (OD-1 п. 1–2) |
| PDF, иначе | значение `document.recognition_route` |
| иной тип | `unsupported` |

Охранник вставки прогона `local_ocr` отказывает (`23514`), если:

- маршрут `unsupported` (OD-4) или `rdweb` (OD-1, D-014: локальный не ставится при имеющемся или идущем RDWeb);
- PDF с маршрутом `auto`, а прогон не несёт автора (`created_by IS NULL`): автоматическое локальное распознавание PDF без явной политики запрещено (OD-1 п. 5, OD-2); явная команда пользователя пишет автора;
- `source_artifact_sha256` не равен SHA-256 оригинала редакции (AD-05a-2: источник — редакция);
- описание распознавателя неполно: нет `recognizerId`, `recognizerVersion`, `inputFormat`, `processing`, `languages`, `config`, или формат не совпадает с типом файла.

Отпечаток считает БД: `sha256` канонического вида `jsonb` описания без служебных полей; хэш конфигурации — `sha256` раздела `config`. Клиент их не передаёт, поэтому расхождения приложения и БД нет. Языки передаются отсортированными.

## 5. Единицы источника и якоря (AD-05a-1)

| Формат | Единица (`unit_kind`) | Размеры | Якорь фрагмента (`locator.kind`) |
|---|---|---|---|
| PDF | `pdf_page` | обязательны у распознанной страницы: растр при DPI распознавателя | `pdf_text`: страница, способ (`native_text` / `ocr`), номер блока |
| XLSX | `xlsx_sheet` (имя листа — `page_label`) | нет | `xlsx_cells`: лист, номер листа, диапазон `A7:F7`, строки и столбцы |
| CSV | `csv_table` | нет | `csv_rows`: записи, столбцы, строка заголовка, физические строки файла |
| DOCX | `docx_body` | нет | `docx_paragraph` или `docx_table_row`: блок, раздел, таблица, строка, ячейки, часть документа |

**Поправка R05a-01 (Review 05a-1, миграция 0015).** «Обязательны у распознанной страницы» оказалось слабее AD-05a-1: у физической страницы PDF размеры есть при любом статусе. CHECK требует их у `pdf_page` при любом статусе, кроме `missing`, охранник вставки — у страницы PDF локального прогона и при `missing`; без размеров остаётся только страница RDWeb, которой нет в экспорте (этап 04, R04-03). Подробно — `data-model.md` §4.4.

Все номера в якоре — с единицы, как их видит человек. Координат у локальных фрагментов нет ни в одном формате (D-014): `bbox_norm`, `polygon_norm`, `bbox_space`, `shape_type` пусты, это проверяет охранник БД. Интерфейс показывает текст и якорь и прямо пишет, что координаты недоступны.

Пустые листы XLSX единицами не становятся и перечисляются в `quality`: пустой лист — не ошибка распознавания. Пустая страница PDF остаётся единицей со статусом `missing`: у физического документа это может быть непрочитанный скан.

## 6. Статусы качества (OD-6)

| Итог для человека | Статус прогона | Когда |
|---|---|---|
| `complete` | `complete` | все единицы прошли шлюз качества |
| `needs_review` | `partial` | есть хотя бы один пригодный фрагмент и хотя бы одна единица `needs_review`, `missing` или `failed` |
| `failed` | `failed` | техническая ошибка, повреждённый или неподдерживаемый файл, превышен предел, нет ни одного пригодного фрагмента |

Новый статус прогона не вводится: `partial` уже означает «результат есть, полноты нет» (A16, I18), заморозка и снимки принимают его с явной неполнотой, `complete` без всех распознанных единиц БД не пропускает. Различие «прочитано, но ниже порога» и «не прочитано» — на уровне единицы: статус `needs_review` против `missing` и `failed`. API отдаёт поле `outcome` со словарём владельца.

Метрики единицы (перенос из Locus, `apps/rag-api/src/converters.js`: `textQualityReport`, `recognitionNoiseReport`, `ocrPageReport`): число символов и слов, доля букв, доля символов замены, доля «шумных» токенов, у OCR — средняя уверенность движка. Числа шлюза фиксируются только после замера корпуса фикстур; распределение и выбранные значения — в отчёте этапа. Пороги входят в конфигурацию распознавателя, поэтому их смена даёт новый отпечаток.

## 7. Конвейер

- Адаптеры — `packages/adapters/src/local/`: безопасный разбор XML без DTD и сущностей, ZIP с пределами распаковки, DOCX, XLSX, CSV, текстовый слой PDF (pdf.js), контракт `LocalOcrEngine` и первый рабочий адаптер на tesseract.js (WASM внутри процесса, модели `rus` и `eng` из npm, без сети).
- Обработчик worker `recognition.local`: класс `default`, приоритет 5 (ADR-004 §7a–7b); heartbeat и проверка отмены между страницами; страницы и фрагменты пишутся финальной транзакцией, как у RDWeb; событие `recognition_run_completed` и дочитывание живых версий индекса — в той же транзакции.
- Автоматическая постановка — проход worker раз в интервал обслуживания: редакции DOCX/XLSX/CSV и PDF с политикой `local` без успешного локального прогона и без прогона с текущим отпечатком.
- Явная команда — `POST /document-revisions/{id}/local-recognitions` с ключом идемпотентности; права — как у приёма RDWeb: `source.write` по тендеру; по договору — редакция видна с `contract.read`, команда требует `contract.manage` (так же принимается экспорт RDWeb в 06a); ответ без содержимого.
- Политика маршрута — `PATCH /documents/{id}` и `PATCH /contract-documents/{id}`, поле `recognitionRoute`.

| Инвариант | После 0014 |

Фундаментальной переделки этапов 04 и 05 проект не требует: все изменения — расширения CHECK, новые необязательные колонки и усиление охранников. Выбор прогона для существующих данных не меняется. Работа продолжается без остановки.
