Роль приложения: `SELECT, INSERT` на неизменяемые; `SELECT, INSERT, UPDATE` на `fact_state`, `fact_remark`, `fact_graph`; `DELETE` нет ни у одной таблицы.

## 4. Функция графа (`computeFactGraph`) — детерминированная

Вход: документы (id, владелец, роль и основной документ 06a, вид, номер, дата, ссылка на основной договор по тексту), факты, решения человека. Выход: связи, состояние каждого факта, замечания, хэш.

1. **Связь.** Роль 06a `addendum` → `amends`, `appendix` → `appendix_of` к `main_document_id`. Документ тендера вида `amendment` / `appendix` (классификатор) → основной договор того же тендера по номеру (и дате, если обе известны); ровно один кандидат — связь; ноль или несколько — связь `unknown` и замечание `parent_not_found` / `parent_ambiguous`.
2. **Допсоглашения** — по дате документа. Для факта допсоглашения с признаком `amends` («пункт N … изложить в новой редакции»): цели — действующие факты того же типа в документах семьи не позже допсоглашения; сначала тот же пункт, иначе единственный совместимый (пункт не указан или тот же); перекрытым ставится `superseded` (`amendment`), `valid_to` = дата допсоглашения, у нового — `valid_from`. Без даты допсоглашение ничего не перекрывает — замечание `undated_amendment`. Несколько совместимых целей без совпадения пункта — ничего не перекрывается, замечание `amendment_target_ambiguous`.
3. **Решения человека** (после правил): `prevails(A, B)` — B перекрыт A (`human`); `distinct(A, B)` — пара независима: снимается перекрытие правилом между ними и конфликт пары; `rule` — пара возвращается правилу.
4. **Конфликт** (донор): действующие факты одного типа в одной семье с разными значениями — `conflict`, кроме пар `distinct`; цена договора и итог сметы одного владельца — группа `total_cost`. Каждая группа — замечание `value_conflict`.
5. **Хэш графа** — от входа (факты, связи, решения): одинаковый вход — одинаковый результат.

Функция одна для двух применений:
- **корпус владельца** (последние редакции документов договора или тендера) — сохраняется в `fact_state`, `fact_remark`, `fact_graph`; пересчёт — в транзакции извлечения и решения человека, под advisory-блокировкой владельца;
- **область ответа** (единицы прогона поиска хода) — в задании ответа: поздний документ вне области не перекрывает пункт в области (I05, ADR-008); решения человека применяются, если оба факта пары в области.

Факт непоследней редакции документа в корпусе владельца — `superseded` с причиной `document_revision`.

## 5. Ответное ядро

- **Пакет**: к результатам поиска добавляются фрагменты фактов запланированных типов (`plan.entities`) в области хода — сначала действующие и спорные, затем перекрытые (донор `factsForPlan`); правило пакета A и выборка `amendmentCandidates` удаляются.
- **Пометка основания**: `conflict` — фрагмент подтверждает факт в конфликте; `superseded` — фрагмент подтверждает только перекрытые факты; иначе `current`. Правило C (замена факта этапа 08) удаляется.
- **R08a-01**: при политике «текущая» утверждение без исторической формулировки, цитирующее хотя бы одно перекрытое основание, отклоняется (`superseded_evidence`); числа сверяются только с неперекрытыми документальными цитатами. Текущая цитата рядом не снимает запрет.

## 8. Границы

- Источник фактов — прогоны распознавания документов тендера и договора. Тела писем и вложения не извлекаются: их права — права ящика (AD-07-1a), экран фактов тендера их бы раскрыл. D-018 разрешает эти происхождения, но не требует их извлечения.
- Правила не угадывают: значение, которое правило не читает однозначно, не извлекается (донор).
- Модель факты не пишет и состояния не меняет; решение человека — ребро графа, а не правка факта.

## 9. Инварианты БД

1. `evidence_fact`, `evidence_fact_fragment`, `fact_extraction_run`, `fact_decision` неизменяемы.
2. Основание факта — фрагмент того же прогона распознавания допустимого происхождения (I06, D-018).
3. Факт пишет только транзакция своего прогона извлечения; у факта есть хотя бы одно основание (COMMIT).
4. Решение человека — два разных факта одного владельца; автор — человек.
5. Состояние — у факта своего владельца; `superseded` ⇔ причина; `superseded_by` — факт того же владельца.
6. Закрытое замечание неизменно.
