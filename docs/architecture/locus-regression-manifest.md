# Манифест переноса регрессионного контракта Locus

Требование ревью 05-pre-1 (AR05-05): число переносимых случаев должно быть проверяемым. Манифест фиксирует каждый из 17 случаев донора, его статус в портале и тест, который его заменяет. Этап 05 заполняет колонку «Тест портала» фактическими именами и отмечает результат; этапы с `deferred` делают то же для своих случаев.

## 2. Как случаи переносятся в портал

- **Проект Locus → тендер портала.** Каждый проект — синтетический тендер; файлы — редакции документов этого тендера с прогоном-фикстурой RDWeb (страницы, фрагменты `recognized_text`). Договор здесь — документ тендера с `doc_type = contract`; договорной контур этапа 06a для этого не нужен.
- **Контекст задаёт тест, а не текст вопроса.** Портал не выбирает проект по формулировке вопроса (D-019): тест передаёт контекст `tender` проекта из `expected.sourceIds`, текст вопроса сохраняется дословно.
- **Уровень утверждения на этапе 05 — поиск, не ответ.** Проверяется, что ожидаемый фрагмент (`expected.evidence[].includes`) есть в top-5 итога прогона поиска этой области, цитата указывает на его страницу, а фрагментов чужого тендера нет. Статус ответа (`verified`, `insufficient_evidence`, `clarification_required`), текст ответа и числовой гейт — ответное ядро (08a).
- **Пороги этапа 05** считаются по случаям со статусом `stage05` на итоге по ветвям `{exact, fts}` — это сопоставимо с базой донора, снятой без векторов: утечка между тендерами равна 0 (жёсткий гейт), Recall@5 не ниже 0,85, MRR не ниже 0,70, точность цитаты равна 1. С моделью на целевом ПК пороги те же, отчёт отдельный.
- **Точность текущей редакции** на этапе 05 измеряется не случаем донора, а RT-02: два прогона одного PDF, в области один (`docs/architecture/test-plan.md` §7). Вопрос «что действует после допсоглашения» — состояние факта (D-018, этап 08), а не ранжирование.

## 4. Результат этапа 05

Тест `tests/searchLocus.test.ts` переносит корпус и прогоняет 9 случаев `stage05` одним сценарием; колонка «Тест портала» — найдено оснований в top-5 и ранг первого релевантного фрагмента. Итог по ветвям `{exact, fts}` (модели нет, сопоставимо с базой донора), ранжирование `r1` (`artifacts/stage-05/locus-regression.log`):

| Метрика | Порог | Значение |
|---|---|---|
| Утечка между тендерами | 0 | 0 |
| Recall@5 | ≥ 0,85 | 0,929 (13/14) |
| MRR | ≥ 0,70 | 0,759 |
| Точность цитаты (основание из ожидаемого документа) | 1 | 1,000 |

Единственный непойманный в top-5 — основание «гарантийный срок» обзорного вопроса (случай 5, 3 из 4). Правила `r1` уточнялись по результатам этого же прогона; каждое уточнение и метрики до него — в отчёте этапа (`docs/stages/05-report.md`), тест манифеста сверяет, что все 17 ID донора размечены и распределение 9/8 не изменилось.

## 5. Порядок ведения

- Этап, закрывающий случай, заменяет «—» в колонке «Тест портала» фактическим именем теста и указывает результат в отчёте этапа.
- Статус меняется только с основанием в отчёте этапа; случай не удаляется. Переход `deferred` → неприменимо — только решением в `docs/decisions.md`.
- Изменение случаев или корпуса в Locus после `95614a8` не подхватывается молча: новый коммит донора — новая строка раздела 1 и пересмотр таблицы.
