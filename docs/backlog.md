# Backlog

## Очередь после первого запуска v1 — D-050, 02.11.2026

Первый запуск принимается по [минимальным критериям v1](releases/v1-acceptance.md). Перенос работы не закрывает дефекты и не меняет их историческую критичность. Задача, фактически нарушающая V1-01…05, возвращается в блокеры запуска с конкретным воспроизведением.

| Порядок | Задача | Сохранённый статус / условие | Влияние на первый запуск |
|---|---|---|---|
| 1 | S18-32: полный анализ, денежные колонки, части условий и доказанные события подач | OPEN/P1; прежние ответы и критерии сохраняются | Вне обещаний v1: модель даёт проверяемые человеком черновики |
| 2 | Полная приёмка пилота 18 по эталону, G1–G7 и М1–М5 | INCOMPLETE; NOT_RUN/0/0 не становятся PASS | Для запуска — один обязательный рабочий цикл V1-02…05; полная оценка качества после запуска |
| 3 | 19-A: корпус, 225 неизвестных, соответствия/алиасы, заморозка, импорт и OCR/ACL | IN_PROGRESS; O19-01…04/08…12 и R19A-03 сохраняются в ветке 19-A | Отдельная миграция; Locus остаётся работающим |

| 6 | S18-14 и прочие открытые/ожидающие ревью замечания правил, извлечения и интерфейса | Статусы defects.md сохраняются; закрытие по существующим доказательствам | До запуска проверять только при влиянии на V1-01…05 |

S18-31 (читаемость нужного скана) и S18-34 (генерация нужного PDF) не объявляются безусловно отложенными: адресно проверяются в V1-03/V1-04. Ошибки доступа, потери оригиналов, неверного выпуска и восстановления всегда блокируют соответствующий сценарий.

API MailHub/RDWeb, внешнее закрытие TenderHub X-01, автоматизация переговоров и остальные расширения остаются ниже. Для v1 действуют ручные пути и решение руководителя D-044; блокировки выпуска не ослабляются.
