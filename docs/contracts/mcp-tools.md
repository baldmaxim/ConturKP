# Контракт инструментов MCP портала

Этап 01: состав и правила. Версия спецификации MCP, SDK и транспорт сверяются с официальной документацией на этапе 16 (ADR-010).

## 1. Общие правила

1. Аутентификация — персональный токен пользователя с областями `read` и `propose`. Права инструмента равны пересечению прав пользователя и областей токена.
2. Область запроса передаётся явно в каждом инструменте: `tenderId` плюс `stageId` или `releaseId`; для сравнения — `leftReleaseId` и `rightReleaseId`. Сервер разворачивает область по ADR-008: для выпуска — из его снимка `evidence_scope`, для этапа — из рабочего состава; права пользователя на ящики применяются поверх снимка при каждом вызове. `scopeHash` пишется в ответ и в аудит.
3. Неоднозначность (несколько тендеров по названию) — ответ `needs_selection` со списком доступных пользователю тендеров: код, название, заказчик. Никаких данных тендеров в таком ответе нет.
4. Ответы ограничены по размеру и пагинированы. Суммы — десятичные строки с валютой, признаком НДС и видом цены. Ссылки на доказательства — ID фрагментов портала.
5. Текст документов возвращается как данные. Инструкции внутри текста не выполняются и не расширяют область (I16).
6. Все вызовы пишутся в `audit_event` с `principal_kind = model_via_mcp` и `on_behalf_of_user_id`.
7. Секреты и внутренние адреса вырезаются из ответов (I17).

## 2. Инструменты чтения (`read`)

| Инструмент | Вход | Выход |
|---|---|---|
| `list_cases` | `search?` | доступные тендеры и этапы: код, название, заказчик, сроки |
| `get_case_overview` | `tenderId`, `stageId` | состав этапа: набор источников, ревизия расчёта, последние проверки, статус готовности |
| `list_documents` | `tenderId`, `stageId`\|`releaseId`, `docType?`, `cursor?` | документы и редакции в области |
| `search_evidence` | `tenderId`, `stageId`\|`releaseId`, `query`, `limit?` | фрагменты: ID, документ, редакция, страница, происхождение, фрагмент текста; поля `scopeHash`, `incomplete`, `semantic` |
| `get_citation` | `fragmentId` | точный текст, документ, редакция, страница, координаты, происхождение |
| `get_calculation` | `tenderId`, `stageId`, `view` (`positions`\|`lines`\|`totals`), `cursor?` | данные закреплённой ревизии расчёта с видом цены, валютой, НДС |
| `get_economics` | `tenderId`, `stageId` | итог, коммерческие составляющие, известные и неизвестные части, статус сверки |
| `list_findings` | `tenderId`, `stageId`, `status?`, `cursor?` | замечания: критичность, уверенность, статус, основания |
| `list_questions` | `tenderId`, `stageId` | вопросы и ответы с редакциями |
| `get_readiness` | `tenderId`, `stageId` | блокеры выпуска, удержания, полнота проверок, состояние размещений и отправок |
| `compare_releases` | `tenderId`, `leftReleaseId`, `rightReleaseId`, `section?` | различия: источники, требования, суммы, условия, причины с их статусом |
| `get_integration_status` | — | статусы интеграций и время последней проверки |

## 3. Инструменты предложений (`propose`)

Все требуют `requestId`; повтор с тем же `requestId` возвращает ту же запись (A37). Результат — `model_suggestion` со статусом `open`, который принимает человек в портале.

| Инструмент | Вход | Что создаёт |
|---|---|---|
| `propose_finding` | `tenderId`, `stageId`, `title`, `body`, `citedFragmentIds`, `severityHint?`, `requestId` | предложенное замечание |
| `propose_question` | `tenderId`, `stageId`, `text`, `citedFragmentIds?`, `requestId` | черновик вопроса заказчику |
| `propose_condition_text` | `tenderId`, `stageId`, `fieldKey?`, `text`, `citedFragmentIds?`, `requestId` | предложение формулировки условия |
| `propose_change_reason` | `comparisonId`, `subjectRef`, `reasonKind`, `text`, `citedFragmentIds`, `requestId` | гипотеза причины изменения |

Валидация до записи: все `citedFragmentIds` существуют и входят в область; иначе `invalid_citation` без создания записи.

## 4. Чего нет

`approve`, `release`, `send`, `resolve_hold`, `accept_risk`, изменение требований, решений, расчёта, пользователей и настроек, произвольный SQL, выполнение команд, доступ к файловой системе и скачивание файлов по пути. Эти действия недоступны MCP-токену на уровне возможностей и на уровне схемы (ADR-006, I12, C03).

## 5. Ошибки

| Код | Когда |
|---|---|
| `needs_selection` | область не задана или неоднозначна |
| `out_of_scope` | запрошенный объект вне области или прав; данные не раскрываются |
| `invalid_citation` | ссылка на несуществующий или чужой фрагмент |
| `not_available` | смысловой поиск или интеграция недоступны (с причиной) |
| `rate_limited` | превышен лимит вызовов токена |
| `forbidden_action` | инструмент требует полномочий человека |
