# Контракт инструментов MCP портала

Этап 01: состав и правила. Этап 16 (D-037): реализация; транспорт, ревизия протокола и SDK сверены с официальной документацией 2026-10-12 (`docs/architecture/16-mcp-design.md` §2). Настройка клиентов — `docs/integrations/mcp-clients.md`.

## 0. Точка и транспорт

- Один MCP-сервер портала в процессе `server`: `POST /mcp`. Транспорт — Streamable HTTP, ревизия протокола `2026-07-28`; клиенты ревизий с рукопожатием `initialize` обслуживаются без состояния. Сессий, потока `GET` и запросов сервера к клиенту нет: `GET` и `DELETE` — `405`.
- Сервер и протокол — официальный SDK `@modelcontextprotocol/server` 2.3.1 (точная версия в `package-lock.json`).
- Включается настройкой `MCP_ENABLED`; по умолчанию выключен (`404`).
- Аутентификация — только `Authorization: Bearer <токен>`; cookie сессии на точке не читается. Нет токена, он неверен, истёк, отозван или пользователь отключён — `401`. Запрос с `Origin` не из разрешённых источников портала — `403`.
- Тело запроса — до 100 КБ.

## 1. Общие правила

1. Токен — персональный, выпускает пользователь в портале (`POST /me/api-tokens`), области `read` и `propose`; `read` есть у каждого токена. Права вызова равны пересечению текущих прав пользователя и областей токена; права загружаются заново на каждый вызов.
2. Область запроса передаётся явно: `tenderId` плюс `stageId` либо `releaseId`; для сравнения — `leftReleaseId` и `rightReleaseId`; для поиска по договору — `contractId` (право `contract.read`). `stageId` — текущий состав этапа; `releaseId` — снимок источников комплекта этого выпуска (документы, поступившие позже, в него не входят).
3. Область не задана — ответ `needs_selection` со списком доступных пользователю дел: код, название, заказчик, этапы. Данных тендеров в нём нет. Портал не выбирает тендер по тексту вопроса (D-019).
4. Ответ — один текстовый блок с JSON. Страница — 20 записей, не больше 50; `nextCursor` — непрозрачная строка, привязанная к инструменту и области. Текст фрагмента — до 2000 знаков с признаком обрезки (полный — `get_citation`). Ответ — до 64 КБ.
5. Суммы считает сервер: десятичная строка, валюта, признак НДС, вид цены (`cost` / `commercial`), ревизия-источник. Нет данных — `null` или `noData` с причиной, а не ноль.
6. Текст документов, писем и расчётов возвращается как данные; описание каждого такого инструмента говорит об этом клиенту. Инструкции внутри текста не выполняются и не расширяют область (I16).
7. Каждый вызов, включая чтение и отказы, пишется в `audit_event`: `principal_kind = model_via_mcp`, `on_behalf_of_user_id` — владелец токена, токен, инструмент, исход. Текст запросов, цитат и предложений в журнал не пишется.
8. Из результата вырезаются токены портала и заголовки `Bearer`, строки подключения с паролем, закрытые ключи, распространённые ключи доступа, пары «имя секрета = значение» и внутренние адреса из настроек установки; на их месте — `[скрыто]` (I17).
9. Лимит вызовов — 60 в минуту и 600 в час на токен (настройки `MCP_CALLS_PER_MINUTE`, `MCP_CALLS_PER_HOUR`).
10. У инструментов нет собственной логики прав: каждый вызывает те же функции чтения и те же проверки закрытости, что и экран портала. Закрытый для пользователя объект возвращается без текста, с признаком `restricted` или `closed`.

## 2. Инструменты чтения (`read`)

| Инструмент | Вход | Выход |
|---|---|---|
| `list_cases` | `search?`, `cursor?`, `limit?` | доступные тендеры и этапы: код, название, заказчик, сроки |
| `get_case_overview` | `tenderId`, `stageId` | набор источников, последняя ревизия расчёта, последняя проверка, последний комплект, выпуски этапа, число открытых предложений из чата |
| `list_documents` | `tenderId`, `stageId`\|`releaseId`, `docType?`, `cursor?`, `limit?` | этап — документы тендера и состав источников этапа; выпуск — единицы снимка источников его комплекта |
| `search_evidence` | `tenderId` + `stageId`\|`releaseId`, либо `contractId`; `query`, `limit?` | создаёт прогон поиска теми же функциями, что `POST /search`: `searchRunId`, `status`, `scopeHash`, `scope`, `semantic`, `final`. Итоговые фрагменты (`fragments`) — только у завершённого прогона; у незавершённого — `preliminary` с пометкой, что итог читается через `get_search_run` |
| `get_search_run` | `searchRunId` | статус и итоговые фрагменты; читает только пользователь, от имени которого создан прогон; права на область пересчитываются при каждом вызове |
| `get_citation` | `fragmentId` | точный текст, документ, редакция, страница, происхождение; адреса скачивания файла нет |
| `list_requirements` | `tenderId`, `stageId`, `cursor?`, `limit?` | требования действующего реестра: код, формулировка, параметры, статус, покрытие, противоречия, ID фрагментов-оснований |
| `get_calculation` | `tenderId`, `stageId`\|`releaseId`, `view` (`totals`\|`positions`\|`lines`), `positionId?`, `cursor?`, `limit?` | ревизия расчёта области (у выпуска — закреплённая комплектом, у этапа — последняя): итоги, позиции, строки |
| `get_economics` | `tenderId`, `stageId`\|`releaseId`, `priceKind?` (`cost`\|`commercial`) | итоги себестоимости и коммерческой цены, составляющие, сверка с итогом источника; итогом КП отчёт не называется. С `priceKind` — итог только этого вида цены; нет такого итога — `noData` (`price_kind_unavailable`) с перечнем имеющихся видов; сумма другого вида вместо запрошенной не возвращается; иной вид цены — отказ |
| `list_findings` | `tenderId`, `stageId`, `status?`, `severity?`, `cursor?`, `limit?` | замечания: вид, серьёзность, уверенность, статус, позиции, требования |
| `list_questions` | `tenderId`, `stageId`, `cursor?`, `limit?` | вопросы заказчику со статусом и ответом; ветки вопросов–ответов тендера |
| `list_decisions` | `tenderId`, `stageId`, `cursor?`, `limit?` | решения по требованиям действующего реестра и решения руководителя по удержаниям |
| `get_readiness` | `tenderId`, `stageId`\|`releaseId` | последний комплект этапа (или комплект выпуска): блокеры, удержания, выпуск, готовность к отправке, размещение, отправки |
| `compare_releases` | `tenderId`, `leftReleaseId`, `rightReleaseId`, `section?`, `cursor?`, `limit?` | сравнение двух выпусков этапа 15 по закреплённым записям: сводка разделов, выводы с доказательствами и статусом причины. Готовое сравнение пары берётся повторно |
| `get_integration_status` | — | статусы интеграций и время последней проверки |

`list_requirements` и `list_decisions` добавлены этапом 16 (спецификация §11, задание этапа). Инструмента `capture_calculation` нет: это действие, а не чтение или предложение.

## 3. Инструменты предложений (`propose`)

Видны только токену с областью `propose`; нужна возможность `mcp.propose` в тендере (инженер и руководитель тендера). Все требуют `requestId` (8–200 знаков). Уникальность — (пользователь, `requestId`): повтор с тем же `requestId` и тем же содержимым возвращает ту же запись с `repeat: true` (A37); тот же `requestId` с другим содержимым — `invalid_request`.

Результат — запись `mcp_proposal` со статусом `open` (этап 01 называл её `model_suggestion`; та таблица хранит только гипотезы прогона проверок). Предложение ничего не меняет в тендере. Принимает или отклоняет его человек в портале (`portal-api.md` §2.11).

| Инструмент | Вход | После принятия человеком |
|---|---|---|
| `propose_finding` | `tenderId`, `stageId`, `title`, `body`, `citedFragmentIds` (1–20), `severityHint?`, `requestId` | замечание от имени принявшего; серьёзность и уверенность задаёт он |
| `propose_question` | `tenderId`, `stageId`, `text`, `citedFragmentIds?`, `requestId` | черновик вопроса заказчику от имени принявшего; вопрос хранит ссылку на предложение |
| `propose_condition_text` | `tenderId`, `stageId`, `fieldKey?`, `text`, `citedFragmentIds?`, `requestId` | записи нет: человек переносит текст в поле приложения сам |
| `propose_change_reason` | `comparisonId`, `itemId` (из `compare_releases`), `reasonKind`, `text`, `citedFragmentIds` (1–20), `requestId` | причина вывода сравнения со статусом «гипотеза» от имени принявшего |

Валидация до записи: каждая цитата существует, читается пользователем сейчас и относится к тендеру области (у причины — входит в снимки этапов сравниваемых выпусков); иначе `invalid_citation` без создания записи.

Принятие не снимает прав на источник (Review 16-1, R16-01). Запись, созданная принятием, несёт все цитаты предложения: замечание и причина — основаниями, вопрос — ссылкой на предложение. Её текст получает только тот, кто читает каждую цитату сейчас: остальным `list_questions` и `list_findings` возвращают запись без текста (`visible: false` / `restricted: true`), в том числе автору предложения после отзыва у него права на источник.

## 4. Чего нет

`approve`, `release`, `send`, `resolve_hold`, `accept_risk`, принятие собственных предложений, изменение требований, решений, расчёта, пользователей и настроек, произвольный SQL, выполнение команд, доступ к файловой системе, скачивание файлов, чтение диалогов портала. Обработчиков этих действий у точки `/mcp` нет; маршруты портала `/api/v1` токен не принимают (`401`); у токена без `propose` инструментов предложений нет и в списке (ADR-006, I12, C03).

## 5. Ошибки

Ошибка инструмента — результат с `isError` и телом `{ error: { code, message, … }, requestId }`.

| Код | Когда |
|---|---|
| `needs_selection` | область не задана; в ответе — список доступных дел |
| `out_of_scope` | объект вне области или прав, либо не существует; одно сообщение для всех случаев, данные не раскрываются |
| `invalid_citation` | цитата не существует, недоступна или не относится к области |
| `invalid_request` | некорректные аргументы, чужой курсор, `requestId` использован с другим содержимым, ответ превышает предел объёма |
| `not_available` | действие сейчас невозможно (с причиной). Недоступный смысловой поиск ошибкой не является: прогон завершается с причиной и итогом по точной и полнотекстовой веткам |
| `scope_changed` | права на часть закреплённой области прогона отозваны; результат не выдаётся, нужен новый поиск |
| `rate_limited` | превышен лимит вызовов токена; `retryAfterSeconds` |
| `forbidden_action` | у токена нет области, которой требует инструмент |
| `internal` | внутренняя ошибка; подробности — в журнале портала по `requestId` |
