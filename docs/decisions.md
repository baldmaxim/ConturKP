### D-004 — Ответы владельца 17.09.2026 (бренд, валюты, устройства)

Дата / автор / основание полномочия: 2026-09-17 / владелец процесса / ответы в рабочей сессии на вопросы `BRAND.md` §13.3.

Проблема: для модели данных и интерфейса нужны валюты расчётов, судьба рабочего названия и приоритет мобильного сценария согласования.

Варианты и последствия: не рассматривались — это ответы владельца, а не выбор разработчика.

Принято:
- корпоративного брендбука пока нет: бренд портала самостоятельный, при появлении брендбука пересматривается;
- название «Контур КП» остаётся на время разработки и затем будет изменено; проверка товарного знака — для финального названия;
- валюты расчётов: рубли, доллар, евро, юань (`RUB`, `USD`, `EUR`, `CNY`); тенге не нужен;
- руководитель будет согласовывать со смартфона: мобильный сценарий согласования обязателен.

Статус: accepted

Что изменяет в требованиях/контрактах/тестах: набор валют в модели денег (ADR-005, `data-model.md` §1); обязательная проверка согласования на ширинах 360–430 px (`test-plan.md`, BRAND.md §9.1); смена названия затронет логотип, `manifest.json` и заголовки.

### D-006 — Технические решения этапа 02

Дата / автор / основание полномочия: 2026-09-18 / Claude / технический выбор в рамках ADR-001, ADR-002, ADR-006.

Проблема: ADR оставили на этап 02 выбор версий, библиотеки паролей, способа запуска TypeScript и границ видимости администратора.

Варианты и последствия:
- пароли: пакет `argon2` (нативная сборка) или встроенный `node:crypto.argon2` (Node ≥ 24.7, без зависимостей, API помечен экспериментальным) — выбран встроенный, формат PHC позволяет сменить реализацию без миграции;
- запуск сервера: сборка `tsc`/`tsx` или встроенное удаление типов Node 24 — выбрано встроенное, без шага сборки; разрешён только стираемый синтаксис;
- администратор без назначения: видит всё или только администрирование — видит карточку тендера и участников, но не этапы и содержимое (ADR-006: «без членства не видит данных тендера»);
- создание этапов: администратор (как в контракте этапа 01) или руководитель тендера — руководитель (`stage.manage`), чтобы у роли руководителя было проверяемое право уже на этапе 02; контракт обновлён;
- тестовая БД: общий кластер разработки или локальный кластер `runtime/pg` на 127.0.0.1:55432 с trust — выбран локальный одноразовый кластер; на каждый файл тестов — своя база `kontur_kp_test_*`.

Принято: как выше; версии — ADR-001 «Реализация (этап 02)»; сессии, CSRF, перебор паролей — ADR-006 «Реализация (этап 02)».

Статус: proposed

Что изменяет в требованиях/контрактах/тестах: `docs/contracts/portal-api.md` §2.1–2.2 (эндпоинты администрирования, `PATCH /stages/{id}`, право `stage.manage`); `data-model.md` §4.1, §4.12 (`process_heartbeat`, `revoke_reason`, `removed_by`, `audit_event.seq`, `principal_kind = anonymous`). Бизнес-требования не меняются.

Ссылка на подтверждение владельца: не требуется для технического выбора.
