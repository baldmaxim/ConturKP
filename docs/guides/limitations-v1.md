# Ограничения первой версии

Что портал не делает и что не проверялось. Источники: `docs/spec/01_PRODUCT_SPEC.md`, матрица `docs/requirements-traceability.md` (C01–C05), итоги эксплуатационной приёмки этапа 17 (D-042).

## 1. Границы продукта

| Ограничение | Что это значит для работы | Основание |
|---|---|---|
| Нет второго OCR/RAG | Поиск и распознавание — только встроенные. Локальный OCR работает лишь для форматов вне охвата RDWeb; при наличии распознавания RDWeb используется оно | C01 |
| Соседние системы не переписываются | TenderHub, MailHub, RDWeb, сервис переговоров остаются самостоятельными; недостающее оформляется внешними доработками (`external-work.md`) | C02 |
| Нет встроенного чата | Codex и Cursor подключаются своим токеном; историю чата портал не хранит как решение, значимое сохраняется действием в портале | C03 |
| Нет автоматической рассылки заказчику | Портал письма не отправляет и черновиков не создаёт; он регистрирует факт отправки, выполненной вне портала | C04 |
| Нет Telegram | Позднее расширение без права согласования (`docs/backlog.md`) | C05 |
| Нет автоматической правки сметы | Расчёт TenderHub портал только читает | спецификация §13 |
| Нет автономных юридических решений | Юридически спорное передаётся человеку | §7, §13 |
| Нет универсального пересчёта чертежей (QTO) | Неопределённость проектной документации превращается в допущение или вопрос | §7 |
| Нет публикации в интернете | Доступ из офисной сети или VPN по HTTPS | §1 |
| Модель не согласует, не выпускает, не отправляет | Все её результаты — предложения; решает человек | I12 |
| «Не найдено» не значит «не предусмотрено» | Пустой результат при неполном распознавании не доказывает отсутствия | I07, I18 |
| Неизменяемость не абсолютна | Защита от действий приложения; администратор ОС или БД формально может изменить данные | I19 |
| Шаблон заказчика не перестраивается произвольно | Форматы приложений — по реальным образцам; демонстрационный шаблон не считается поддержкой всех форм; результат DOCX/XLSX проверяется глазами | §8 |
| Не больше двух инженеров и одного руководителя на тендер | Ограничение базы данных | §1 |
| Время — по Москве | Хранится с поясом, показывается в МСК | §12 |

## 2. Блокеры боевого выпуска

Пока не сняты, итог — не «готово к эксплуатации» (решение владельца):

| Блокер | Состояние | Что нужно |
|---|---|---|
| Q-01 / X-01 — закрытый расчёт | TenderHub не отдаёт неизменяемую закрытую ревизию (внешняя блокировка). Внутри портала закрытым считается ревизия, зафиксированная решением руководителя (D-044) | решение руководителя на каждую ревизию; X-01 остаётся открытым (`external-work.md`) |
| Q-05 — итог КП | правило D-044: итог расчёта TenderHub, НДС включён; боевой выпуск требует ещё сверки экономики ревизии (толкование на проверке) | новая выгрузка с итогом источника; сверка `reconciled` |
| Q-08 — реальные формы | пока на демонстрационных шаблонах; реальные формы проверяет владелец | недемонстрационные утверждённые шаблоны |

Тестовый выпуск этими блокерами не ограничен, но заказчику не отправляется.

## 3. Эксплуатационные ограничения (итог приёмки этапа 17, D-042)

| Ограничение | Подробности |
|---|---|
| Импорт RDWeb на паузе | Решение владельца 2026-10-20. Порог SLO для импорта RDWeb не утверждён; замер на синтетическом корпусе не заменяет работу с настоящим экспортом. API RDWeb нет (X-05): экспорт загружается вручную |
| MailHub автоматически не читается | Машинного доступа нет (X-03). Штатный путь — ручной импорт файлов EML; автоматического подтверждения отправки нет |
| Сервис переговоров не подключён | Только импорт файла `kontur.negotiation.v1` (Q-06) |
| SLO действуют только для профиля D-040 | Целевой ПК, 10 000 позиций, ~30 000 строк расчёта, до 1 ГиБ Markdown. Утверждённые значения: импорт расчёта ≤ 30 с; индексация и векторизация корпуса 1 ГиБ ≤ 4 ч 30 мин; полный поиск p95 ≤ 15 с; проверка синтетического этапа ≤ 30 с; сборка DOCX/XLSX/PDF ≤ 30 с; копия базы ~6 ГБ и файлов ~424 МБ ≤ 2 мин. Для других объёмов и ПК значения не гарантируются |
| Поиск по тексту до ~11 с (S17-24) | Полнотекстовая ветка медленнее требования 1–2 с, хотя укладывается в SLO p95 ≤ 15 с. Первая индексация большого корпуса занимает часы (замер — около 3,5 ч на 1 ГиБ) |
| Качество модели не принималось | Проверен механизм (ответы приходят, эмбеддинги считаются), качество договорных ответов, гипотез и предложений не оценивалось; пороги — по итогам пилота (Q-11). Любой вывод модели проверяйте по цитате |
| Модель зависит от входа пользователя | LM Studio работает в сеансе пользователя; без входа смысловой поиск и ответы недоступны, проверки помечаются неполными |
| Один слот GPU | Тяжёлые задания идут по одному |
| Яндекс Диск | Через локальную папку синхронизации; облако подтверждает человек. Работа клиента Диска без сеанса пользователя не утверждается: без входа файлы в облако не уйдут |
| Не проверялось | Реальный исторический выпуск в рабочей базе, многопользовательская нагрузка, время восстановления большого корпуса, графические клиенты Codex и Cursor (проверены CLI), реальные формы до решения Q-08 |
| Копии | Зеркала копией не считаются; автоматического удаления старых копий нет, политика хранения — решение владельца |
| Рост служебных таблиц | Задания, сессии и записи идемпотентности не очищаются автоматически |
| Лимиты запросов | Хранятся в памяти одного процесса server: рассчитаны на одну установку |
| S15-08 | Регистрация отправки требует решения руководителя по письму — открыто, решение владельца |
| Известные дефекты интерфейса | S17-28 — переполнение страницы на 8 px при ширине окна 1118 px (P3); исправление — этап 18, состояние уточняется по `docs/defects.md` |
| Уязвимость pdfjs-dist | Смягчена: сценарии pdf.js не используются, политика CSP запрещает чужие скрипты; обновление библиотеки — отдельной правкой |

## 4. Что считается готовым в первой версии

Полный цикл от источников до тестового выпуска, размещения и копии работает и проверен на целевом ПК. Ввод в эксплуатацию (боевой выпуск) определяется итогом пилота этапа 18 и снятием блокеров §2.
