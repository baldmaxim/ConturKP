# Q-08: проверочные комплекты генподряда

Статус этапа: **код этапа 18 принят; локальный релиз установлен; пилот и итоговая приёмка не проведены**. Эта доработка готовит комплект для просмотра владельцем. Утверждение шаблонов, приёмка цены, отправка заказчику и финальный пилот ею не выполняются.

Реализованы общие скалярные параметры и формулировки подачи, отдельные даты цен/БСМ, корпоративные 28 пунктов на одном А3, выбор методики и её редакции, позиция заказчика только с подтверждением и источником. Внутренние пометки и расчёт содержания не печатаются. Подготовленные приложения закрепляются по SHA-256; исходная печать сохраняется. Допускается только согласованная обработка пустых удельных цен групп; исторические исходники не перезаписываются.

Каждая правка сохраняет неизменяемую редакцию входа, каждая сборка — байты DOCX/XLSX/PDF и manifest. Новая подача копирует прежние условия в отдельный черновик. Интерфейс показывает историю, состав изменений и устаревшую сборку после правки. Стандартные проверки выпуска и согласования остаются отдельным процессом; проверочный комплект не создаёт кандидата выпуска.

Владелец уточнил прежнее Q-05 для этого генподряда: номинированные разделы отсутствуют в TenderHub и добавляются при сборке отдельными строками с явно заданной базой НДС и генподрядным процентом. Уже включённый НДС повторно не начисляется. Подытог TenderHub берётся из связанной редакции расчёта, а не из свободного поля. Для первого просмотра выбраны твёрдая цена с перечисленными исключениями, единый коэффициент армирования и расчётный итог; историческая оферта — отдельный источник сверки. Коммерческие значения находятся в частной описи целевого ПК.

Дополнительная сверка оферты выявила различия основной базы и отдельную БГ номинированной части. Четыре дополнительных работы ПД уже присутствуют в TenderHub, повторно добавлять их нельзя. Свежая шапка TenderHub расходится с суммой всех позиций; S18-17 открыт. Проверочный комплект показывает это предупреждение, manifest закрепляет обе суммы. Причина расхождения источника и коммерческая приёмка цены не установлены.

Уточнение после чтения контракта и локальных исходников TenderHub: cached_grand_total предусматривает отдельное страхование сверх коммерческих сумм, а D-030 прямо отмечает недоступность страхования, снижения и финансовой детализации по сервисному ключу. Сравнение шапки только с позициями не доказывает ошибку TenderHub. Остаток запрещено объявлять страхованием по одному вычитанию. Предупреждение комплекта означает незавершённую расшифровку состава, а не установленный дефект арифметики источника; S18-17 уточнён как ограничение интеграции. Подытог источника не заменялся суммой позиций.

По результатам сверки владелец изменил условие: БГ на исполнение требуется, обеспечение — 3% полной цены договора с номинированными разделами и генподрядным вознаграждением; комиссия банка — 3% годовых на срок строительства. Для первого черновика этот срок связан с единым полем 30 месяцев, без дополнительных месяцев передачи. Комиссия добавляется к цене с НДС КП 22%, без генподрядных 14%. Итог и комиссия согласуются между собой с десятичным округлением: размер БГ берётся от окончательной цены, включая прибавку за её комиссию. Банковский расход, прибавка к цене и размер обеспечения показаны раздельно; тариф и внутренний расход в текст заказчику не выводятся. Это предварительный расчёт без предложения банка. Старые постоянные расходы БГ не переносятся.

Новая миграция 0051 добавляет только таблицы проверочных комплектов и неизменяемой истории. Миграции 0046–0050 перенесены в рабочую копию без изменений из действующей локальной установки, чтобы не перезаписывать параллельную историю/Office. Установка делается точечным объединением с текущим сервером и сборкой текущего интерфейса, с резервной копией и проверкой исходных SHA. Коммерческие образцы и JSON в Git не включаются.

Проверки: целевые регрессии форм, расчёта, прав, истории и существующего выпуска — одним потоком на отдельном PostgreSQL. Ошибка выражения в новой проверке высоты исправлена и проверка повторена; исходное падение не скрывается. Типы сервера/интерфейса и сборка проверяются отдельно. Полный набор проекта повторно не заявляется. Печатные страницы письма, методики и лист А3 просмотрены; Excel проверил итоговые ячейки производной старой оферты без сохранения источника.

До приёмки остаются несогласованные реквизиты договора и нумерация приложения методики, содержание трёх дополнительных корпоративных пунктов, выбранная исполнительная документация и просмотр комплекта владельцем. Для иных механизмов/порогов потребуется отдельная содержательная и печатная проверка; подготовленный первый комплект использует выбранный механизм. Q-08 и этап 18 остаются открытыми.

Установка выполнена по `38acfa3` и `bb3eff1`, миграция 0051. Перед ней сохранены полная БД (pg_dump custom, проверены список архива и SHA-256), изменяемые файлы, интерфейс и конфигурация с исходными ACL. При подготовке обнаружены параллельные изменения Office/истории: интерфейс пересобран из актуальных исходников, чужие изменения сохранены. Перезапущен только server, worker продолжал работать. Health/ready PASS. Через обычный API создан первый проверочный комплект: 12 файлов, пять исходных приложений, реальные не-demo шаблоны остаются draft. SHA всех выданных файлов проверены, 27 оригиналов повторно сверены с сетью и не изменены. Коммерческая опись, квитанции и резервная копия остаются на целевом ПК вне Git.

Последний прогон после расчёта БГ: 22/22 в трёх файлах; ранее 54 связанных проверки обычных форм/утверждения/выпуска прошли в отдельном однопоточном наборе. Типы и сборка актуального интерфейса PASS. Фактические файлы портала: условия — один А3, письмо — пять страниц, методика — три; DOCX отрисованы отдельно. Браузерная проверка интерфейса не выполнена: runtime браузерного инструмента не инициализировался; получение нового bundle и API не выдаётся за визуальную QA интерфейса. Ни отправки, ни утверждения шаблонов, ни финальной приёмки этапа не выполнялось.
