## S18-31: исчезающие изображения PDF

У pdf.js 5.7.284 не был задан локальный `wasmUrl`. При JBIG2/CCITT движок сообщал `Ensure that the wasmUrl API parameter is provided`, затем не мог загрузить `nulljbig2_nowasm_fallback.js`; `page.render` при этом мог успешно вернуть пустой холст. В результате читаемый скан давал `no_usable_text`.

Исправление задаёт локальный каталог `pdfjs-dist/wasm/` с прямыми разделителями и завершающим `/`. В идентичность только PDF-распознавателя добавлена версия рендера: прежний частичный результат не переиспользуется как результат исправленного кода. DOCX/XLSX/CSV этим не меняются. При установке сохраняется параллельный `parserVersion: 2` установленного XLSX-разборщика.

Регрессия `tests/localPdfCodecs.test.ts` использует искусственный CCITT-PDF: без исправления чёрная область исчезала (0 тёмных пикселей), после исправления декодируется. Проверены локальные пути Windows и Linux. Две новые проверки PASS, 34 существующие PDF/parser-проверки PASS, TypeScript PASS. Это профильная проверка; прежний полный результат ветки остаётся 1704/1705 с открытым S18-30.

Дополнительно исправленный код прочитал одну страницу реального сканированного протокола: `complete`, 14 фрагментов, 2133 символа. Проверка выполнена отдельно, без записи результата в рабочую БД. SHA-256 исходного PDF на сетевом ресурсе до и после совпал. Частные исходники и текст протокола в Git не включены.

Владелец отдельно разрешил штатную отмену остатка старой PDF-пачки, короткий перезапуск служб с двухфайловым патчем и повтор через штатный API, начиная с протокола. Фактический результат установки и повторного прогона фиксируется в частной квитанции; разрешение само по себе не означает успех установки.

Установка выполнена: изменены только `local/pdf.ts` и PDF-часть `local/recognizer.ts`, сделаны копии прежнего кода, SHA 63 защищённых файлов не изменились. Параллельный XLSX `parserVersion: 2` сохранён, миграций нет. Через штатный API отменён фактический остаток — 33 задания; поставлен повтор 91 PDF, начиная с протокола. Службы работают, `/ready` положителен. Новый штатный прогон протокола с `renderingVersion=bundled-codecs-v1` — `complete`, 1/1 страниц, 14 фрагментов, без потерянных страниц; результат подтверждён в интерфейсе.
