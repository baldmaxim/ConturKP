## Принятые решения

| Предмет | Решение владельца |
|---|---|
| Ввод чисел и сроков | Один ввод с подстановкой в текст существенных условий и письма; значения согласуются для конкретной подачи |

| Следующая подача | Переносить предыдущие условия в черновик, показывать изменения и заново согласовывать итоговый комплект; историю предыдущей подачи сохранять |
| Содержание стройплощадки | Расчёт внутренний; в КП выводить только согласованную месячную компенсацию |

| Методики компенсации | Шаблоны по механизмам с подстановкой реквизитов и согласованных параметров; использованную редакцию сохранять в истории подачи |

| Позиция заказчика | В портале с источником; в форму подставляется подтверждённая редакция; внутренние пометки команды отдельно |
| Перечень исполнительной документации | Выбор из библиотеки по составу работ для каждой подачи с сохранением редакции |
| Пороги компенсации | Задавать для каждой подачи, не ограничивать 0% и 5%; текст условий и методика должны соответствовать механизму и введённым значениям |
| Расчётные приложения первой версии | Подхватывать готовые оферту, БСМ и ГПР из связанных источников подачи и закреплять версии файлов; итог КП — TenderHub по Q-05 |

Согласие с этими требованиями не является утверждением `proposed/`, всех текстов исходной схемы или исторических условий. Реальные шаблоны и формулировки в рабочую БД не загружались.

## Выполненная проверка

Локально вне Git учтены 27 файлов: 9 XLSX, 14 DOCX, 3 DOC, 1 PDF. У всех 27 после основной проверки исходные и скопированные байты совпали по SHA-256. Девять XLSX прочитаны без сохранения, шесть небольших книг напечатаны отдельным Excel в режиме ReadOnly без пересчёта и обновления связей. Из 14 DOCX извлечён текст, три документа дополнительно отрисованы штатным `render_docx.py`; просмотрено 12 страниц. Исторический PDF просмотрен на пяти страницах; одна страница имеет только растровое изображение и не является пустой.

Три старых DOC содержат два различных набора байтов. Оба уникальных документа дополнительно отрисованы из локальных копий отдельными профилями LibreOffice: 7 и 2 страницы; текст извлечён, миниатюры всех девяти страниц просмотрены. Три копии сохранили SHA-256. Это контрольный рендер LibreOffice, не проверка печати Microsoft Word или полноты перечней для новых работ.

Все 25 заголовков исторической таблицы сопоставлены с корпоративными 28. Три пункта отсутствуют в ней как отдельные строки; это не доказывает отсутствие соответствующих условий во всём комплекте. При переносе применяется сопоставление по смыслу; нумерация исторических пунктов с корпоративной не совпадает.

Корпоративная форма действительно печатается на одном А3 с мелким шрифтом; владелец выбрал сохранить этот вид. Подозрения на обрезку трёх концов текста проверены увеличенными фрагментами и не подтвердились. Печатный вид после подстановки новых текстов ещё предстоит проверить.

Выявлены разночтения повторяющегося технического значения в одном комплекте, неверная ссылка на пункт письма, устаревшие реквизиты в образцах и конфликт ссылок на приложения в методике и действующем договоре. Дата получения цен и дата БСМ различаются по смыслу — не считаются ошибкой только из-за различия дат. Полные значения, документы, ячейки, изображения и квитанции остаются на целевом ПК вне Git.

Для вопросника печать разрывает связанные колонки на разные группы страниц; график и БСМ существенно уменьшены. После отдельного вопроса владелец выбрал сохранить исходную печать всех приложений. Новые макеты не требуются; при подстановке проверяется полнота вывода и сохранение исходного оформления.

Прежний анализ 52 ошибок деления в исторической оферте использован после сверки того же SHA-256: ошибок в зависимостях итогов не было, 21 контрольный итог при пересчёте сохранился, ошибки видны в проверенных печатных страницах. Для будущего шаблона владелец выбрал пустую ячейку удельной цены группы без количества, с сохранением итогов. Исходник не изменён. Универсальное скрытие ошибок Excel этим не предлагается.

## Что остаётся

В исходной схеме 76 полей: 54 text, 18 number, 2 choice, 2 table; отдельных полей дат нет. Одновременное наличие целого текста пункта и вспомогательных чисел не доказывает автоматическую подстановку. Пороги — числа, но выбор методики закрыт восемью комбинациями 0%/5%; это требует переработки по принятому правилу. Единый ввод между условиями, письмом и методиками принят как требование; реализация и генерация на реальных шаблонах ещё не подтверждены.

Проверки для будущей разработки: одинаковые вхождения значений между документами; две независимые даты; изменение новой подачи без подмены старого комплекта; параметризованная методика и правильные ссылки; подтверждённая позиция заказчика с источником; версия перечня; разделение внутренней стоимости и компенсации; пустая удельная цена группы без изменения итогов; полный вывод подстановок с сохранением исходной печати. Это перечень проверок, не выполненные тесты.

Основные подходы согласованы, ожидающих ответа вопросов сейчас нет. Следующие содержательные вопросы — после подготовки образца: тексты конкретной подачи, состав и номера приложений, источники значений с разночтениями. Автоматический подбор файлов именно для выбранной карточки этим проходом не включался.

2. Подготовить разметку корпоративных 28 пунктов, письма и методик. Устранить устаревшие реквизиты и неверные ссылки в новой редакции; исходники не править. Нумерацию приложений КП и договора учитывать отдельно.
3. Привязать данные и файлы к конкретной подаче: предыдущие условия — новый черновик, изменения видны, новое согласование обязательно, прежний комплект и версии неизменны. Внутреннюю стоимость содержания не смешивать с согласованной компенсацией.
5. Выполнить проверки связей значений, истории подач и печати по перечню выше, затем предъявить владельцу сгенерированный комплект. Основные условия — один А3, приложения — исходные настройки печати. Только после проверки и приёмки реальных шаблонов решать о снятии демо-ограничения.
