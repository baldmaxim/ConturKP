# S18-32: подтверждённая причина отказов, 29.10.2026

> Обновление после диагностики: владелец снял запрет, контекст действующей загрузки поднят до 16384 и четыре вопроса повторены. Контекстный отказ устранён, содержательная приёмка FAIL. См. `18-s18-32-technical-replay-20261029.md`; ниже сохранён исторический срез до разрешения.

Статус дефекта: **OPEN P1**, G7 FAIL. Диагностика выполнена без новых запросов LM Studio, без изменения рабочей установки, профиля/загрузки модели, источников и эталона. Ветка: `codex/s18-32-diagnostics-20261029`, база `4e54c2f` после завершённого ручного smoke установки.

## Причина четырёх отказов

Сопоставлены четыре сохранённых answer_run, их параметры из рабочей БД (READ ONLY) и архивный серверный журнал LM Studio за **26.10.2026, 18:01:52–18:02:39 МСК**. В этом окне четыре chat-запроса к qwen3-4b-instruct-2507, во всех max_tokens=4096.

| Тема | Вход, токены по LM Studio | Результат LM Studio | Код портала |
|---|---:|---|---|
| advance | 2033 | 15 токенов ответа, finish_reason=length; сумма 2048 | model_truncated |
| retention | 3533 | Engine HTTP 400, exceed_context_size_error, n_ctx=2048 | model_contract_mismatch |
| award | 3769 | Engine HTTP 400, exceed_context_size_error, n_ctx=2048 | model_contract_mismatch |
| price-history | 3932 | Engine HTTP 400, exceed_context_size_error, n_ctx=2048 | model_contract_mismatch |

Все четыре технических отказа объясняются ограничением загруженного контекста. Первому запросу оставалось 15 токенов, а остальные три входа превышали 2048 ещё до генерации. Три contract_mismatch здесь пришли из адаптера: обработчик HTTP/ответа провайдера возвращает этот общий класс, а answer handler сохраняет coverage.modelError. До parseDraft они не дошли. Переписывание JSON-схемы ответа не является выявленным исправлением.

## Проверенные параметры и границы вывода

- Сохранённый профиль Qwen: contextLength=2048, advertised maxContextLength=262144. Это наблюдение 26.10; текущая загрузка LM Studio 29.10 ещё не запрашивалась. Второй сохранённый профиль с контекстом 8192 относится к другой модели.
- Портал на 29.10 настроен на тот же Qwen через http://127.0.0.1:1234: maxInputChars=3000, maxOutputTokens=4096, jsonMode=none. Ответное ядро: packetLimit=12, verifierMode=off, maxRepairs=1. Параметры совпали с inference_config четырёх прежних прогонов.
- maxInputChars описывает символьный предел пачки фрагментов. Он не задаёт окно LM Studio и не учитывает токены системной инструкции, шаблона чата и ответа. Answer handler выбирает до 12 элементов, а draftUserContent берёт до 1400 символов каждого. Одно значение 3000 не является доказательством вместимости полного запроса.
- SHA системного промпта, заново рассчитанный текущей чистой функцией draftSystemPrompt по четырём сохранённым планам, во всех случаях совпал с БД: e09c167c3512856134ef4f078426e9d914dd13819cf1127a87349304beebbebb. Инструкция: 1685 символов / 2791 байт; эти размеры не подменяют токеновые счётчики.
- Debug-журнал сокращает system/user content до представлений по 127 символов с отметкой Truncated in logs. Размеры и хэши этих представлений нельзя выдавать за полный payload. Токеновые числа в таблице взяты из usage и диагностик движка. Фактическое новое полное сообщение и его бюджет надо проверить при повторе.
- Наибольший записанный вход 3932 плюс запрошенные 4096 токенов ответа дают 8028. Контекст 8192 оставил бы только 164 токена запаса для этого случая. Для подготовленного повтора предложен минимум **16384**, запас относительно записанного начального бюджета — 8356. История, исправления и новый отбор могут изменить вход; 16384 не объявляется универсальной гарантией для любых вопросов.

## Подготовленный следующий шаг

Машинный план: `docs/ops/18-s18-32-replay-plan-20261029.json`; точные вопросы и новые idempotency keys — в локальном replay-plan.private.json. План ещё не выполнялся.

1. После снятия ограничения владельцем прочитать текущую загрузку только целевого Qwen, сохранить профиль и проверить наличие свободных ресурсов. Если текущий контекст уже достаточен, не перезагружать его. Если меньше 16384 — изменить только профиль/загрузку этого Qwen при простое; другие модели не выгружать. При невозможности загрузки вернуть прежний профиль.
2. Сохранить maxOutputTokens=4096 и остальные настройки портала. Проверить вместимость полного нового запроса, включая системное сообщение, вопрос, пакет, историю и резерв ответа. Увеличение одного max_tokens не устраняет недостаток окна.
3. Создать четыре технических диалога через штатный API, с прежним замороженным evidenceScopeId и точными прежними вопросами. Свежие диалоги исключают добавление старой переписки. Старые четыре результата не переписывать; исходники, снимок и эталон не менять.
4. Запускать последовательно через обычные answer jobs/GPU slot; после первого повторного переполнения/обрыва остановить оставшуюся часть пакета. Встроенные ограниченные повторы разбора и исправления сохраняются; это четыре вопроса, а не обещание ровно четырёх HTTP-вызовов. Фактические вызовы и повторы записать отдельно.
5. Сверить input/config/prompt SHA, действительные токеновые счётчики и причины отказов. Если новый пакет отличается от старого input_sha256, отразить дрейф отбора отдельно. Затем проверить показанные утверждения, цитаты, релевантность вопросу и первичные источники. Для аванса отдельно проверить прежнее замечание о выборе ПД вместо основных условий ДГП.

Один корректный JSON ещё не подтверждает пригодный проход. S18-32 остаётся OPEN до полезного штатного результата и его проверки. Технические диалоги не засчитываются за действия двух инженеров/руководителя; G1–G6 и итоговая приёмка этим повтором не закрываются.
