## Как готовится кандидат

1. Область v1 и бэклог фиксируются отдельным коммитом этой ветки.
2. Зависимости сверяются с package-lock. Локальный offline npm ci остановился: в кэше отсутствует zod 4.6.5; чистая установка не объявляется успешной. Для подготовки используется установленное дерево с идентичным lock; все девять workspace-ссылок должны вести в эту рабочую копию. На целевой установке зависимости также должны соответствовать lock.
3. `node scripts/ops/build-release-v1.mjs` проверяет типы, собирает web и включает commit в HTML/version.json до генерации Service Worker. Исходный HTML не переписывается.
4. `python scripts/package-release-v1.py --out <новый ZIP>` создаёт локальный пакет из Git-файлов выбранного commit и его web/dist. .git, зависимости, .env, рабочие базы и runtime не включаются. Манифест содержит SHA-256 каждого файла и идентификатор сборки; рядом записывается SHA-256 ZIP.
5. Кандидат не означает установку или приёмку. Квитанция подготовки — `v1-preparation.json`, машинная квитанция сборки — `runtime/release-v1/build.json`, квитанция пакета — рядом с ZIP.

Пакет содержит исходники Node/TypeScript и собранный web. Это поставка для существующего Windows runbook, не автономный установщик с PostgreSQL, Node, LibreOffice и зависимостями.
