## Замечания

### R00-01 — P2: неверное описание авторизации Dify

Место: `docs/discovery.md:98`.

Утверждение «POST /api/dify/retrieval проходит без токена» основано только на исключении маршрута из общего middleware. В той же зафиксированной ревизии LocalAI `c03a3c4` обработчик POST в `apps/rag-api/src/server.js` вызывает `authorizeDifyAdapterRequest`. Функция из `apps/rag-api/src/dify-adapter.js` проверяет отдельный `LOCALAI_DIFY_ADAPTER_TOKEN`: при отсутствии настройки возвращает 503, при отсутствующем/неверном токене запроса — 401.

Влияние: следующий архитектурный этап получает неверную карту авторизации и может принять защищённый адаптер за анонимный маршрут либо спроектировать ненужный обход/дублирование auth.

Исправление: написать «маршрут исключён из проверки общего RAG_AUTH_TOKEN, но защищён отдельным токеном Dify-адаптера в обработчике», добавить ссылки на обработчик и функцию. Также уточнить, что возможность отключить общую авторизацию определяется не только отсутствием токена, но и RAG_REQUIRE_AUTH.

Проверка закрытия: прочитать полный путь middleware → handler → authorizeDifyAdapterRequest в указанной ревизии; не объявлять endpoint открытым по одному `next()`.

### R00-02 — P2: неполная проверка RDWeb может завершиться PASS

Место: `artifacts/stage-00/verify_discovery.py:140-144`, `:175-176`.

При отсутствии RDWeb-архива `check_rdweb()` печатает SKIP и возвращается, не отмечая ни ошибку, ни неполноту. Итог зависит только от `failures`, поэтому при остальных успешных проверках получается PASS и exit 0, хотя часть обязательной проверки источника не выполнена.

Воспроизведение: импортировать модуль, направить `RDWEB_ZIP` на отсутствующий файл, вызвать `check_rdweb()`. Получено: `SKIP образец RDWeb недоступен`, список failures пуст, итоговое выражение из main даёт PASS.

Влияние: независимый reviewer на другой машине может принять неполную проверку за полное воспроизведение этапа. Это противоречит правилу пакета об отделении непроверенного от успеха.

Исправление: в полном режиме отсутствие обязательного материала даёт BLOCKED/FAIL и ненулевой exit. Если нужен режим проверки только документов — включать его явно, выдавать PARTIAL с перечнем непроверенного. Для отсутствующего архива API сейчас после FAIL возникает FileNotFoundError; оформить отсутствие материалов в единый понятный результат, не обрывающий остальные независимые проверки traceback.

Дополнительно желательно разрешить явные пути/manifest для трёх репозиториев и двух архивов: единственный --workspace предполагает структуру машины Claude, которой нет на целевой Windows-машине. Это не ошибка бизнес-логики, но мешает заявленной воспроизводимости.

Проверка закрытия: тесты «все материалы доступны», «нет RDWeb», «нет API ZIP», «нет нужной Git-ревизии», «явно выбран частичный режим». Только первый получает полный PASS.
