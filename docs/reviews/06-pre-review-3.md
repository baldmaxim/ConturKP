## R06-01

Исправление принимается.

### Первая линия — PortalCaptureStrategy

`boq-items-full` теперь проверяется на уникальность ID строки.

Сценарий:

`A, B, C → A, A, C`

при сохранении:

- общего числа строк;
- `items_count`;
- состава позиций;
- контрольных признаков шапки;

даёт:

`item_duplicated`

и:

`consistency = inconsistent`.

Нормализованное содержимое не создаётся, `calculation_revision` не создаётся.

Таким образом дефект обнаруживается до ограничения уникальности БД.

### Вторая линия — БД/worker

Fallback (резервная защита) ограничен корректно.

PostgreSQL `23505` считается `content_rejected_by_db` только для:

- `calculation_position_key`;
- `calculation_line_key`.

Другие нарушения уникальности не переклассифицируются глобально.

Если дефект всё же достигает БД:

- capture завершается `failed`;
- причина — `content_rejected_by_db`;
- ошибка считается детерминированной;
- повторного выполнения задания нет;
- повторного чтения TenderHub нет;
- содержимое не создаётся;
- ревизия не создаётся.
