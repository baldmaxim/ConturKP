R08-03. Исправить нормализацию значения параметра конфликта в `0020_requirement_checks.sql`.

Сейчас И-08-16 говорит, что числовые значения сравниваются без незначащих нулей, однако `requirement_param_value()` выполняет только `trim`, замену запятой на точку, удаление пробелов и `lower`. Поэтому `100`, `100.0` и `100.00` считаются разными и создают ложный конфликт.

Нужно разделить канонизацию числа и текста.

Для значения, которое является корректным числом после допустимой нормализации записи, формировать каноническое числовое представление через PostgreSQL `numeric`, чтобы как минимум:
- `100` = `100.0`;
- `100` = `100,00`;
- `100` ≠ `100.1`.

Не применять числовую нормализацию к смешанным обозначениям типа `B30`, `IP54`, `5x10`.

Для текстового значения зафиксировать отдельное правило нормализации. Не удалять внутренние пробелы без явно принятого решения; предпочтительно `trim + lower + collapse whitespace`.

Единица остаётся частью ключа значения после `unit_normalize`.

Добавить тесты API и второй линии БД:
1. `100 мм` против `100.0 мм` — конфликта нет;
2. `100,00 мм` против `100 мм` — конфликта нет;
3. `100 мм` против `100.1 мм` — конфликт;
4. одинаковое число, разные единицы — конфликт;
5. смешанное текстовое значение (`B30`) не интерпретируется как число;
6. пояснение к конфликту при численно одинаковых значениях отклоняется как `conflict_note_unexpected`.

Обновить И-08-16 точным описанием числовой и текстовой нормализации и отчёт Stage 08.
