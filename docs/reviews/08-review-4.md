## R08-05 — воспроизведение и причина

Файл: apps/worker/src/handlers/intake.ts:124. Связанный код: packages/storage/src/index.ts:72–75.

Триггер: Windows, каталог хранилища задан путём через junction; цель существует, подкаталоги хранилища требуется создать или проверить. В текущей среде временные пути используют короткое имя профиля ODINTS~1.A.

Фактическое поведение: BlobStore.ensureDirs вызывает mkdir(..., { recursive: true }) через путь junction и получает ENOENT. В handleIntakeScan этот вызов расположен перед try/catch, который должен записать отказ канала. Поэтому resolveChannelRoot и проверка overlaps_storage не выполняются, а lastErrorCode остаётся null. Исключение обрабатывается внешним рантаймом задания как ошибка, но предусмотренный результат канала отсутствует. Незаконное чтение хранилища этим воспроизведением не доказано; дефект состоит в необработанном отказе и невыполненном сценарии проверки пересечения.

Минимальное воспроизведение без БД:

1. Создать временный BASE, каталог BASE/root и BASE/root/a.
2. Создать junction BASE/alias → BASE/root.
3. Выполнить mkdirSync(BASE/alias/a/store/sha256, { recursive: true }).
4. В этой Windows-среде получено ENOENT. То же для tmp и derived; физический store не создан.

Тесты, независимо повторённые отдельным запуском:

- tests/intakeOverlap.test.ts:54 — хранилище внутри папки, путь через alias: ожидается overlaps_storage, получено null.
- tests/intakeOverlap.test.ts:64 — папка внутри хранилища, путь через alias: ожидается overlaps_storage, получено null.
- tests/regressions-r03.test.ts:280 — хранилище через junction: ожидается overlaps_storage, получено null.

Ожидается: вычислить/использовать физический путь при подготовке хранилища так, чтобы штатная инициализация через junction работала на Windows, затем обнаружить пересечение с первого скана. Ошибка подготовки хранилища должна корректно отражаться в состоянии канала/задания, не оставляя ложного отсутствия ошибки. Только перенос ensureDirs внутрь catch не закрывает обязательные overlap-сценарии: они по-прежнему должны выдавать overlaps_storage. Проверки ослаблять или пропускать Windows-сценарии нельзя.
