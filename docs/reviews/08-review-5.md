## R08-08 — ожидания путей в тестах, P3

Файл: tests/intakeOverlap.test.ts:99–100 и :112.

На Windows с временным путём через короткое имя профиля ODINTS~1.A асинхронный fs.promises.realpath, используемый продуктом, возвращает полное имя odintsov.a.a. Обычный realpathSync, которым тест строит ожидание, сохраняет короткую запись. Тест сравнивает строки одного физического пути и падает:

- ожидается C:\Users\ODINTS~1.A\AppData\Local\Temp\…;
- получено C:\Users\odintsov.a.a\AppData\Local\Temp\….

Второй тест останавливается на этом сравнении до снятия junction и записи объекта. Поэтому два FAIL исходного suite не доказывают сбой продукта, но нарушают требование зелёного полного Windows-прогона.

Минимальное воспроизведение: npx vitest run tests/intakeOverlap.test.ts --maxWorkers=1 --fileParallelism=false на данной Windows-машине. Полный исходный прогон показал ровно эти два отказа.

Минимальная правка: вычислять ожидание тем же native/асинхронным способом, например realpathSync.native(ROOT) и realpathSync.native(target), либо сравнивать физическую идентичность; сохранить все проверки отсутствия создания, снятия junction, записи и целостности объекта. Не приводить строки только к нижнему регистру: это не устраняет различие коротких и полных имён.

Для диагностики создана отдельная копия теста, где изменены только два вызова вычисления ожидаемого пути на realpathSync.native. Все 9/9 тестов копии проходят на Windows без изменения кода продукта или исходного тестового файла. Копия после прогона убрана из каталога tests. Это диагностический результат, а не зелёный результат исходной передачи.
