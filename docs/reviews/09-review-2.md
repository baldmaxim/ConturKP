## R09-04 — P1: сохранённый вход модели обходит отзыв прав после запуска

Место: `apps/worker/src/handlers/review.ts:129–136` (и отправка пачек ниже). При исправлении R09-02 удалены `loadAccessContext` / `readableFragments` перед выполнением модели. Теперь обработчик берёт готовый `model_input` и отправляет его без проверки текущего доступа запустившего пользователя.

Нормативная основа: ADR-006, раздел закрытости производного текста: отзыв права скрывает текст сразу, вход модели ограничен читаемыми запустившим фрагментами. I05 ограничивает обработку правами; I17 распространяет права исходника на фрагменты. Снимок входных данных нужен для воспроизводимости и не фиксирует право доступа навсегда. Прежнее решение R08-02 о закрытости производного текста сохраняется.

Воспроизведение через штатные API и worker:

1. Инженеру и руководителю доступны письмо и почтовый ящик. Создать и подтвердить требование с основанием из этого письма.
2. Инженером запустить проверку. Выполнить только `review.run`, оставив `review.model` в очереди.
3. Администратором отозвать у инженера `mail.read` обычным API назначения прав ящика.
4. Убедиться через `GET /requirements/:id`: ответ 200, `restricted=true`, текст требования скрыт.
5. Выполнить `review.model` с поддельной моделью, записывающей полученный запрос.

Получено на `8be22a7`:

```json
{"requirementRestricted":true,"modelCalls":1,"protectedLetterSent":true}
```

В модель передан полный текст уже недоступного письма и производная формулировка требования из сохранённого входа. C12 помечен **passed**, `restricted=0`, `requirements=1`: используются прежние права, хотя API уже применяет отзыв. Утечка подтверждена в фактическом аргументе `IChatCompleteInput.user`, а не только наличием текста в таблице снимка. Внешняя модель не использовалась.

Контроль на `28a447e`: тот же независимый тест проходит, `modelCalls=0`, `protectedLetterSent=false`, C12 **incomplete**, `restricted=1`, `requirements=0`. Это регрессия исправления, а не прежний дефект или особенность Windows.

### Требуемое исправление

Сохранить неизменяемый набор данных R09-02, но перед передачей модели проверять текущую активность/область пользователя и текущий доступ ко всем основаниям производного текста. Отозванное право должно исключать закрытое требование целиком либо прекращать проверку гипотез с понятной причиной неполноты. Проверять закрытость с учётом всех ролей оснований и наследования текста по правилам R08-02; нельзя заменять сохранённые редакции текущими и тем самым возвращать R09-02.

Покрыть как минимум отзыв `mail.read` между заданиями правил и модели; дополнительно проверить отзыв назначения по тендеру/договору и деактивацию запустившего. Если модель получает несколько пачек, учитывать актуальность прав перед отправкой очередной пачки. C12 и показатели неполноты должны отражать исключённые входы.
