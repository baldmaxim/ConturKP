## 3. R10-03 — CLOSED

Миграция **0028** заменяет `change_basis_supersession`, добавляя проверку следующей `qa_item_revision`. API и оба DB-триггера 0027 используют обновлённую функцию. Принятые миграции 0001–0027 не менялись, что соответствует ADR-002.

Прежний независимый сценарий выполнен без изменения ожиданий:

1. Импортирован ответ об увеличении площади штукатурки до 110 м2.
2. Импортирована следующая редакция того же вопроса: прежнее разъяснение отменено, площадь остаётся 100 м2. Проверена связь `supersedes_revision_id`.
3. События инвалидации обработаны; в момент проверки необработанных событий этапа **0**.
4. Новый действующий ответ допускается: **200**, `basisChanged=false`.
5. Старый ответ отвергается: **409**, `current.reason=basis_superseded`, причина `qa_item_revision_superseded`. Новая версия причины не записана.
6. Прямая запись старого ответа в БД отвергается с **SQLSTATE 23514**; транзакция откатывается, новая версия не создаётся.

Авторская регрессия дополнительно подтверждает отказ **до и после** обработки события, сохранение прежней истории и допустимость действующего ответа. Проверка покрытия типов источника проходит: функция актуальности содержит ветку для каждого разрешённого типа `evidence_fragment.source_unit_type`.

Доказательства: `windows-independent.log`, `independent-evidence.json`, `reviewer10b.test.ts`, `tests/reviewRegressions10b.test.ts` в проверенном коммите.

## 4. R10-04 — CLOSED

Фильтр `changed=true` теперь учитывает сохранённую диагностику изменения строки, включая `unit_changed`. Прежний независимый сценарий `100 м2 × 10 RUB` → `1 000 000 см2 × 0,001 RUB` выполнен без изменения ожиданий:

- Себестоимость остаётся **1000 RUB**, коммерческая сумма — **1200 RUB**.
- Фиктивных вкладов объёма/цены нет; сохранены два нулевых `not_decomposable` с `reason=unit_changed`, единицами `м2` → `см2`.
- Позиция присутствует в ответе `GET /comparisons/{id}/units?changed=true&limit=200`.
- В настоящем браузере, при включённом по умолчанию «только изменившиеся», позиция «Штукатурка стен» видна сразу, с текстом причины и обеими единицами. После снятия фильтра диагностика также сохраняется.

Браузерный сценарий ревьюера использует две выгрузки одной версии, настоящие server + worker и отдельную БД. Его отсутствие в авторском `ui-check.mjs` не оставляет этот случай непроверенным: независимый скрипт прошёл **24 / 24**.

Авторские проверки подтверждают видимость смены единицы как при нулевой, так и при ненулевой дельте; сопоставимые неизменные позиции остаются вне списка. Неизменные строки с отсутствующим курсом или неприменимой формулой больше не создают нулевой шум «без разложения». Несопоставимые позиции по-прежнему видимы. Версия метода — `compare/10-3`; результаты прежних методов сохраняются как записаны.

Доказательства: `windows-independent.log`, `windows-reviewer-unit-ui.log`, `reviewer-ui-shots/390-unit-change-filter-on.png`, `390-unit-change-filter-off.png`, `reviewer-ui-unit-change.mjs`.

```powershell

```

```powershell
npx vitest run tests/reviewer10.test.ts tests/reviewer10b.test.ts tests/reviewRegressions10.test.ts tests/reviewRegressions10b.test.ts --maxWorkers=1 --reporter=verbose
```

Для повторения браузерного случая положить `reviewer-ui-unit-change.mjs` в `artifacts/stage-10/`, задать `CHROME_PATH` (при необходимости `UI_SHOTS`) и выполнить `node artifacts/stage-10/reviewer-ui-unit-change.mjs`. Для обычной UI-проверки — `node artifacts/stage-10/ui-check.mjs`; регрессия — скрипты этапов 02–09, для ранних также задан `EDGE_PATH`.
