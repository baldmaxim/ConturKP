## Закрытие R11-03

Решение по требованию без собственных цитат теперь закрепляет конкретную ревизию требования. Функция источников раскрывает фрагмент исходного ТЗ через эту закреплённую ревизию.

Независимо подтверждено:

- До замены документа запись поля по решению и завершение приложения проходят — положительный контроль.
- После новой редакции исходного документа API отвечает `409 basis_superseded`; прежнее значение показывает `stale: true`. Прямая запись основания через БД получает SQLSTATE `23514`, причина `document_revision_superseded`.
- После изменения самого требования старое решение продолжает ссылаться на прежнюю ревизию и отвергается с `requirement_revision_superseded`. Новое решение по новой ревизии снова позволяет записать поле.
- После обработки событий worker запрет сохраняется.
- При обновлении схемы с 0030 на 0031 два ранее записанных решения закрепились за ревизиями, действовавшими в момент каждого решения. Раннее решение не было подменено последней ревизией; повторная миграция ничего не применяет.

На `4604b16` независимый сценарий замены ТЗ возвращает **200**, а прямая запись в БД фиксируется без отказа. На `3f5b46e` оба сценария проходят с требуемыми отказами. **R11-03 — CLOSED.**

## Закрытие R11-05

Актуальность скопированного значения проверяется по всей цепочке источников. Проблема исходного основания видна у текущей копии; подтверждение не очищает её.

Независимо подтверждено:

- После двух обсуждений и замены документа все версии в истории и текущая копия показывают `stale: true`. Причина `document_revision_superseded` возвращается у текущей версии. Подтверждение и завершение через API — 409.
- Прямое подтверждение устаревшей копии в БД — SQLSTATE `23514` с причиной замены документа.
- Перенос после замены документа сохраняет текст и причину устаревания. Отчёт содержит исключённое основание; подтвердить или завершить приложение нельзя.
- Свежая цепочка из трёх обсуждений подтверждается с восстановлением исходного основания; завершение проходит.
- Уже подтверждённая копия также устаревает после замены источника. Прямое завершение приложения через БД отвергается с `basis_superseded`.
- Новое самостоятельное ручное значение без прежнего основания можно сохранить и завершить — исправление не запрещает разрешённый ввод инженера.

На `4604b16` текущие копии после обсуждения и переноса имеют **`stale: false`**, а подтверждение свежей копии теряет основания. На `3f5b46e` соответствующие проверки проходят. **R11-05 — CLOSED.**
