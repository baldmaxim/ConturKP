## Что блокирует исполнение

Прежний тестовый PostgreSQL с pgvector находился в Docker, порт `127.0.0.1:55432`. В начале этой проверки порт не слушал, Docker Desktop не работал. Установленная служба PostgreSQL 16 не использовалась и не менялась.

Запуск Docker сначала завершался на оставшихся файловых сокетах: `Docker/run/sailor-ingest.sock`, `docker-secrets-engine/engine.sock`, затем `Docker/vm-data/00000002.000007cf`. Каталоги сокетов сохранены переименованием; `vm-data` перед переименованием проверен: в нём был ровно один файл длиной 0 с атрибутом ReparsePoint, указанный в диагностике. Виртуальные диски и данные контейнеров не переносились и не удалялись. Настройки Docker не менялись. Останавливались только процессы Docker, запущенные в ходе восстановления; процессы других проектов не завершались.

После этого Docker смог запустить виртуальную машину `linux/sailor`, но соединение гостя с Windows продолжило отказывать: `virtio_vsock::muxer`, `failed to connect`, `os error 10022`; Docker API и порт БД остались недоступны. Сохранены краткая диагностика и состояние среды. Это отказ среды выполнения, не найденный дефект ConturKP.

Владельцу задан вопрос о восстановлении Docker либо предоставлении другой изолированной тестовой БД PostgreSQL ≥17 с pgvector. После восстановления достаточно продолжить из этой копии, повторно распаковывать передачу не требуется.
