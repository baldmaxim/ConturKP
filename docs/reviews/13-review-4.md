## Независимое подтверждение R13-06 и контролей

Сохранён сценарий предыдущего ревью: после завершённого прогона документ с требованиями меняется штатным PATCH из `other` в `contract`. Отпечатки приложения и SQL v3 меняются и совпадают между собой. Старый прогон становится устаревшим; `candidate_gate_problem` возвращает `REVIEW_OUTDATED`, API согласования — **409**, прямая транзакционная проба согласования — **SQLSTATE 23514** с тем же блокером. Проба откатывается. Новый прогон читает изменившийся `fromContract` и выполняет договорную проверку C07: это изменение смысла проверки, а не только подписи.

Дополнительный сценарий меняет тип уже **после согласования**: выпуск через API получает **409**, прямая проба записи выпуска в БД — **23514 / REVIEW_OUTDATED**. Старое согласование не позволяет обойти изменившийся вход.

Контроль: переименование документа и смена способа распознавания не меняют отпечаток и не устаревают завершённый прогон; следующая смена типа его устаревает. Решение между двумя извлечёнными фактами записано настоящей командой API: меняются оба отпечатка и актуальность прогона. Отпечатки SQL/приложения совпадают в UTC, Europe/Moscow и Pacific/Honolulu.

Девять прежних сценариев сохраняют проверки закрытых причин рисков/удержаний, манифеста и архивов, запретов закрытых решений, вечного исключения выпуска после «влияет», сверки `compositionHash`, изменений реестра до сборки и после согласования, немаксимального вопроса и контрольного неизменённого комплекта. Диагностический SQL обновлён с v2 на v3; ожидаемые запреты не ослаблены.
