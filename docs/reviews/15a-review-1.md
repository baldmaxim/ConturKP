## S15-14 — защита повторов подтверждена

Независимо проверены четыре команды: создание допущения, замечания, кандидата требования и вопроса заказчику с закрываемым основанием из письма. Первый запрос читает основание законно и возвращает полный ответ. Без изменения прав повтор возвращает ту же запись и тело. После отзыва `mail.read`, при сохранённых роли и участии в тендере, повтор по прежнему ключу получает **409 `STATE_CONFLICT`, причина `replay_unavailable`**. Закрытой формулировки в ответе нет, число записей не растёт.

Запись прежнего формата, вставленная без отпечатка прав, тоже даёт 409 и не выполняет команду повторно. Исходные тесты дополнительно проверяют расширение и восстановление прав, доступ к договору, отпечаток каждого вида выдачи, коллизии ключей и чужого пользователя.

По коду отпечаток включает все виды прав из `IAccessContext`: роли, действующие назначения, выдачи по договорам, `contract.create` и выдачи по ящикам. Контекст загружается заново на каждый HTTP-запрос; отключённый пользователь не проходит аутентификацию. Порядок элементов не влияет на отпечаток. Защита включена общей обёрткой для команд, сохраняющих тело; четыре команды этапа 15 с собственным `replay` продолжают строить представление по текущим правам.

Инвентаризация автора различает 79 объявлений и 82 маршрута. Это не 82 независимых исполняемых проверки. Отдельный тест на каждую из 26 команд класса C не выполнялся; выборочная проверка и общий путь защиты подтверждены. Историческое число 26 берётся из инвентаризации автора, а не из повторного воспроизведения всех старых отказов ревьюером.

Поведение после возврата прав соответствует принятым тестам: если текущий набор прав снова равен исходному, ответ доступен. Отпечаток фиксирует состояние прав, а не историю всех промежуточных изменений. Изменение закрытости объекта при неизменных правах пользователя (например, добавление нового закрытого основания) автор явно исключил из объёма 15a; это ревью не объявляет такой сценарий проверенным.

## S15a-01 — проверка первого ответа подтверждена

Пользователь без чтения ящика видит гипотезу закрытой при чтении прогона. Первый запрос отклонения такой гипотезы получает **409 `restricted_fragments`**, текст не возвращается, гипотеза остаётся открытой. Читающий пользователь отклоняет её с 200. После отзыва у него `mail.read` идемпотентный повтор этого успешного отклонения даёт 409 без текста гипотезы. Эти сценарии проверены независимо; исходные три теста также прошли.

Полный аудит первых ответов всех старых команд не выполнялся и не подменяется исправлением S15a-01.
