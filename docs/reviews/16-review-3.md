## Независимая проверка неизвестной истории

`reviewer16Unknown.test.ts` создаёт дополнительные данные настоящим старым кодом, затем применяет **0041 + 0042**:

- **Потерянная промежуточная связь:** вопрос создан без требования, затем связан с закрытым и отвязан двумя прежними API-командами. После обновления `basisUnknown: true`, текст скрыт через API и MCP `list_questions`; правка, отправка и замена связи открытым требованием получают **409**.
- **Нет аудита создания:** контрольная запись обычной SQL-командой роли приложения получает неизвестную историю и закрывается по требованиям этапа. Текст видит читающий все основания руководитель; инженер без доступа — не видит.
- **Обычный вопрос:** создан без связи и отмечен отправленным одной прежней командой; после обновления открыт, `basisUnknown: false`.
- **Избыточное закрытие:** дважды правленный вопрос, который ни с чем не связывали, получает `basisUnknown: true` и закрывается для не читающего все основания. Это заявленная консервативная граница, подтверждённая отдельно.
- **Вторая линия:** прямое снятие `basis_unknown` отвергается **55000**; попытка стереть массив оснований не стирает накопленные связи.
- **Версии и текущие права:** миграция сохраняет версии вопросов. Выдача права на договор открывает вопрос; отзыв снова скрывает его.

Результаты: `outputs/independent-unknown-observations.json`. Пять независимых тестов проходят. Набор «все требования этапа» покрывает возможные прежние связи: внешний ключ не позволяет ссылаться на требование другого этапа, требования и история не удаляются.
