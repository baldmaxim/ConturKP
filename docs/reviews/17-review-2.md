## R17-05 — успешная копия чужого кластера при отсутствующем psql (P1)

**Место:** `scripts/ops/backup-lib.ts:87–92`, `scripts/ops/pgTools.ts:74–77`. `findPgTools` принимает Docker-инструмент с `psql=null`. `runBackup` тогда пропускает проверку system_identifier и полагается на экспортированный снимок. Комментарий «чужой кластер его не знает» неверен для совпавшего имени снимка.

**Воспроизведено настоящими pg_dump/pg_restore на двух отдельных PG18**, а не подставным инструментом:

1. В обоих кластерах одинаковая схема 43, роли и имя `kontur_kp_snapshot_route_test`. В таблице `reviewer17_snapshot_marker` исходная база содержит `SOURCE_ONLY`, другая — `WRONG_CLUSTER_ONLY`.
2. На другом контейнере после его полной инициализации временно убраны из PATH оба psql; исходный контейнер и PostgreSQL не изменены. Настройка инструмента указывает на другой контейнер, BACKUP_DATABASE_URL — на исходный. `findPgTools` действительно возвращает `mode=docker`, `psql=null`.
3. Другой кластер держит два обычных экспортированных снимка: `00000006-00000002-1` и `00000007-00000002-1`. `runBackup` на исходной базе экспортирует `00000007-00000002-1`.
4. pg_dump другого контейнера принимает совпавшее имя снимка. Копия **успешна**, публикует завершённый манифест; дамп 1 501 143 байта, SHA-256 `6af3b742e02a0b7105b76972f472d058f6350fcf3069a67c5462aa1ea6053a8b`.
5. Чтение таблицы из custom-дампа через `pg_restore --data-only --table=reviewer17_snapshot_marker --file=-` возвращает код 0: `WRONG_CLUSTER_ONLY` присутствует, `SOURCE_ONLY` отсутствует.

Журнал: `outputs/independent-snapshot-routing.log`; сценарий: `independent/reviewer17.snapshot-routing.ts`.

**Контроли:** при несовпавшем имени снимка pg_dump отказывает уже на стадии снятия; это не идентификация кластера. После возвращения psql неверный контейнер отвергается по разным system_identifier. Правильный инструмент снимает дамп с `SOURCE_ONLY`, без `WRONG_CLUSTER_ONLY`. Журналы всех контролей сохранены.

**Влияние:** система может объявить копию исходной базы завершённой, хотя в ней другая база. Совпавшее имя снимка не доказывает происхождение данных. В стандартном образе psql присутствует, и проверенный обычный маршрут защищён; дефект относится к разрешённому запасному режиму без psql.

**Требуемое исправление:** без надёжной сверки фактического маршрута копия должна отказывать до pg_dump. Практичный вариант — сделать psql обязательным и для копии, как уже для проверки восстановления. Не заменять сверку кластеров проверкой наличия снимка. Добавить регрессию, включая совпавшие имена снимков, и поправить комментарий/описание границы защиты.
