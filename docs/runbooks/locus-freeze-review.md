# 19-A: полный обход, перенос пути и таблица владельца

Все выходы частные и создаются в новых каталогах. Приложения/службы/конфигурация Locus не меняются. SHA подтверждает прочитанные байты, но не происхождение файла, полноту корпуса или решение владельца. Код полного обхода первого живого прохода — fc72634; точные SHA CLI/реализации записаны в каждом результате. Последующая проверка лимитов CLI до создания выходов не меняет чтение допустимых входов.

## Полный обход

В JSON `roots` перечислить активный data root (`kind=data_metadata`), все конфигурационные корни оригиналов (`kind=originals`) и родителей индексных путей вне конфигурации (`data_metadata`, происхождение не подтверждено). Каждый корень имеет неизменный rootId и абсолютный path. Полный обход охватывает все файлы/каталоги, включая неиндексированные; data/cache перечисляются по метаданным и не выдаются за оригиналы.

```powershell
node scripts/ops/locus-freeze.mjs --roots '<roots.private.json>' --out-dir '<new-private-dir>' --portal-root '<portal-installation-root>' --max-bytes 120000000000 --max-ms 3600000
```

Оригинальные корни читаются потоково с SHA-256, размером, mtime/ctime максимальной доступной точности и идентичностью до/после. Junction/symlink не обходятся; исчезновение, изменение во время чтения, чувствительные файлы, лимиты и ошибки остаются видимыми. Полный список не усекается с флагом complete=true. Повторные физические пути могут использовать проверенное чтение при тех же метаданных внутри одного прохода; объём statistics.hashedBytes относится к прочитанным уникальным путям, не уникальным SHA. Путь из индекса сам по себе не подтверждает SHA.

Выходы: inventory.private.json, progress.private.jsonl. Exit0 означает завершённый технический обход, exit2 — частичный, exit1 — ошибка входа/IO. Даже exit0 сохраняет contentSnapshotPreserved=false, D046Compliance=NOT_PROVEN и retirementAllowed=false: байты отдельного корпусного снимка ещё не сохранены, замороженная пара не принята. Стабильность пары и backup-window проверяет compareFreezePair; отсутствие ошибок этого сравнения тоже не снимает человеческие гейты.

## Подтверждённая владельцем смена физического корня

Не переписывать конфигурацию Locus или исходный manifest. Сохранить прямой ответ владельца, старый/new root, sourceIds и время в отдельной relocation-квитанции. Новый корень прочитать отдельным полным проходом. Комбинация проходов — составная подготовительная опись с разными окнами, не атомарная заморозка.

```powershell
node scripts/ops/locus-walk-registry.mjs --walk '<first-inventory.private.json>' --replacement '<relocated-inventory.private.json>' --relocation '<owner-root-relocation.private.json>' --derived-copies '<owner-md-provenance.private.json>' --registry '<saved-current-manifest.json>' --sources '<source-catalog.json>' --out-dir '<new-derived-dir>' --portal-root '<portal-installation-root>'
```

deriveFullWalkRegistry сохраняет sourceId/entryId и объявленный старый путь; физический путь чтения переносится только по подтверждённому корню и неизменному относительному пути. Исходная область по binding по-прежнему определяется из объявленного пути независимо от совпадений SHA в портале. Кэш, неподтверждённый источник, конфликтующие SHA одного пути и неизвестные байты не становятся проверенными оригиналами. Для owner-подтверждённых MD-копий требуется отдельная derived-copies-квитанция с точными sourceId/entryId: их SHA сохраняются только как производные. MD перечитываются с SHA; читаются только поля заголовка Document/Path, тело/URL/команды не используются. Совпадения PDF/DOCX в том же подтверждённом корне предлагаются с approved=false. Для отсутствующих сетевых файлов возможны предложения того же имени только внутри настроенного источника: размер/имя не подтверждают редакцию/область, document.sha256 остаётся null. Предложения не подменяют решения владельца. Новые/неиндексированные файлы полного обхода сохраняются отдельно как **неутверждённые кандидаты**: не каждый файл в корне является договором, и они не импортируются автоматически.

## Свежая копия портала

После завершённого первого контрольного обхода, до второго, вызвать штатный runBackup через версионированную обёртку. Окружение загружается Node из установленного файла, значения секретов не выводятся:

```powershell
node --env-file='<installed-env-file>' scripts/ops/locus-portal-backup.mjs --backup-root '<configured-backup-root>' --receipt '<new-private-backup-receipt.json>'
```

Требуется BACKUP_DATABASE_URL роли kontur_backup, STORAGE_ROOT, BACKUP_ROOT и инструменты PostgreSQL. Явный backup-root обязан совпасть с настроенным физическим корнем. Используются принятые проверки роли/кластера/снимка, pg_dump и файлов; retention не вызывается даже при наличии его конфигурации. Службы, схема, приложение и прежние копии не меняются. Неудачная копия очищает только собственный новый каталог стандартным механизмом; источники/прежние копии не удаляются. Новая копия без двух пригодных обходов не является замороженной парой.

## Таблица владельца

Пересчитать portal/classification штатным locus-corpus-workflow на новых зафиксированных входах; отдельно сохранить SHA всех входов. Затем:

```powershell
node scripts/ops/locus-owner-review.mjs --registry '<saved-current-manifest.json>' --locus '<derived-dir>/inventory.private.json' --portal '<analyzed-dir>/portal.private.json' --classification '<analyzed-dir>/classification.private.json' --tables '<extracted-dir>/tables.private.json' --sources '<source-catalog.json>' --out-dir '<new-owner-review-dir>' --portal-root '<portal-installation-root>'
```

Выходы: JSON всех исходных идентичностей, HTML с фильтром и суммы. Роли документа, связи с основным документом, редакции, архивность своего/чужого договора, группы повторного target и все неизвестные сохранены. В таблице нет автоматической подписи/импорта; humanReviewed=false, все решения null. Подписание окончательного crosswalk требует актуальной пары, имени/даты владельца и SHA точного утверждённого файла. Предварительную таблицу на старом backup не подписывать как гейт A. 500/459 не являются окончательным составом импорта.
