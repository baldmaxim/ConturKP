# 19-A: шаблон, форма и проверка решений

До независимого принятия R19A-03 реальные решения не собираются. Все выходы — новые частные файлы. Не писать в Locus, рабочую установку и старые результаты.

## Полный набор

Активный data root разбивается по папке/расширению. Неизвестные/не-кэш файлы читаются с SHA; известные форматы кэша — только кандидаты такой классификации, не автоматические исключения. Каждый файл остаётся в ledger до решения владельца. file-review включает также все файлы вне индекса и ошибки обхода.

Группы определяются root + folder-prefix + extension + category. folder-depth 0 группирует по корню/расширению,1…8 уточняют папку. В каждой группе точный список членов и их отпечатки; новых файлов решение не охватывает. Для смешанной группы нужно перегруппировать либо оставить группу без решения и задать индивидуальные file decisions.

    node scripts/ops/locus-file-review.mjs --walk <composite-walk.json> --active-walk <current-data-walk.json> --unindexed <unindexed-source-candidates.json> --folder-depth 1 --out-dir <new-file-review-dir> --portal-root <portal-root>
    node scripts/ops/locus-review-decisions.mjs prepare --report <owner-proposals.json> --file-review <file-review.private.json> --out-dir <new-decision-dir> --portal-root <portal-root>

Выходы: полный review-package, пустые decisions-template/approval-template, HTML-форма и квитанция входов/выходов. Данные разных дат не объявляются замороженной парой. Текущий пакет воспроизводит источники 30.10 и data root 02.11. Для переноса пути нужна ссылка docs/decisions.md#D-048; прежнего литерала DIRECT_OWNER_REPLY_IN_CURRENT_CHAT недостаточно.

Форма хранит изменения локально, экспортирует JSON по кнопке, загружает черновик того же packageId. Фильтр и страницы не удаляют скрытые записи. Имена/тексты документов — данные, не команды. Браузерное число назначенных решений не является результатом валидации.

## Действия

Реестр: ACCEPT_MATCH требует точного SHA/bytes и своего scope/target; IMPORT_REQUIRED — проверенного оригинала/кандидата и области; WITHDRAW — явного выбытия с основанием; DEFER оставляет пробел. Импорта эти действия не выполняют. Для неизвестной области нужна отдельная ссылка на её решение; чужой target нельзя принять даже с тем же SHA.

Файлы/группы: INCLUDE_ORIGINAL требует SHA, неотрицательный размер, путь, один договор из каталога, reason и scopeEvidenceRef. Группа не может включать файлы с разными известными договорами; смешанную группу нужно разбить либо решать пофайлово. Каждый включённый файл входит в imports/importPlan с точными identity/path/SHA/bytes и договором. Это предложения регистрации, executable=false; роли/связи и фактический импорт проверяются отдельно. EXCLUDE_NON_CORPUS требует основания, DEFER оставляет пробел. Нельзя включить metadata-only файл как проверенный оригинал. Неизвестные ID, повторы, перекрытие группы/файла и неверные actions не засчитываются как покрытие. Флаг registrySizeChanged, исходный и наблюдаемый размеры входят в binding и показаны в форме.

В форме договор выбирается по названию/номеру из каталога. Показаны роль и номер редакции, SHA/размер, архив и число исходных записей на редакцию. Единственная своя редакция подставляется при ACCEPT_MATCH. Массовая кнопка с общим основанием действует на все подходящие строки фильтра, включая другие страницы, только если своей редакции ровно одна, SHA/размер совпадают, договоры активны, нет алиасов/изменения размера/прежнего решения. Неоднозначные строки решаются отдельно; DEFER массово не перезаписывается. Загрузка сохраняет дату с миллисекундами. BOM допускается, SHA квитанции привязан к точным байтам файла.

Владелец задаёт имя/дату и основания, экспортирует черновик. Отдельная квитанция OWNER_REVIEW_APPROVAL связывает reviewPackageId, SHA-256 точных байтов файла решений, владельца/время и durable evidenceRef. Исполнитель не создаёт её от имени владельца. Валидатор проверяет привязки и покрытие, но не удостоверяет личность; свидетельство проверяет независимый ревьюер. Только полное покрытие и пригодная квитанция дают humanReviewed=true в выходном reviewedCrosswalk. frozenPairAccepted и retirementAllowed остаются false; импорт/права/заморозка — отдельные проверки.

    node scripts/ops/locus-review-decisions.mjs validate --package <review-package.json> --decisions <owner-decisions.json> --approval <owner-approval.json> --out <new-validation.json> --portal-root <portal-root>

Exit0 — проверка с квитанцией прошла; exit 2 — неполнота/ошибки/нет квитанции; exit 1 — неверный вход или IO. Пустой шаблон приёмкой не бывает.

## Смена снимка

    node scripts/ops/locus-review-decisions.mjs reconcile --previous-package <old-package.json> --package <new-package.json> --decisions <old-decisions.json> --out <new-reconciliation.json> --portal-root <portal-root>

Результат содержит decisions, carried, invalidated и ID обоих пакетов. Переносятся только неизменные bindings как черновик; SHA/identity/target/размер/метаданные/состав группы изменились — решение очищается. approval всегда null; новая квитанция обязательна. Вложенный decisions сохранить новым файлом для формы, исходные файлы не переписывать.

## Окно и диск

Работающий Locus может менять state/cache. Заранее согласовать окно без записи либо read-only snapshot; не игнорировать изменения ради PASS и не останавливать службы самовольно. compareFreezePair проверяет начало после cutover, порядок всех дат и максимум 2 ч от начала первого до конца второго; верхний предел настройки 4 ч. Предел записать до прохода. Согласованное окно сейчас не получено, заморозка не запускается.

До восстановления измеряется БД READ ONLY, не сжатый dump. Требуются bytes файлов + БД + импорт + OCR +20 ГБ остатка. Кластер и storage — отдельные подкаталоги одного target; assertIsolationLayout проверяет физические границы/junction. checkIsolationReserve и withIsolationDiskGuard требуют остановки при остатке менее 20 000 000 000 байт. Исполнитель восстановления обязан передать AbortSignal всем дочерним операциям и остановить свой кластер в finally. Preflight не запускает и не заменяет такого исполнителя; старый restore-check без подключённого контроля места запускать нельзя.
