## 3. MailService = MailHub

Это уже действующая кодовая база почтового сервиса; утверждение «API пока нет» уточняется: API интерфейса есть, машинный контракт для портала ещё требуется подтвердить/добавить.

Прочитанные исходники:

- `backend/app/api/v1/router.py`: префикс `/api/v1`, роуты messages, attachments, users и другие.
- `backend/app/api/v1/messages.py`: list feed с cursor, фильтрами, thread_id; карточка с body_text/body_html, participants, attachments, occurrences; чтение цепочки.
- `backend/app/api/v1/attachments.py`: content, preview, inline с проверкой видимости вложения.
- `backend/app/api/deps.py`: пользовательская cookie-session, CSRF для записей, роли и AllowedAccounts.
- `backend/app/infrastructure/models.py`: mail item IDs, message_id, sent_at, attachments.
- README описывает IMAP/worker, PostgreSQL, локальный агент LM Studio, существующие черновики/уведомления. Некоторые описания ролей README устарели относительно кода; использовать актуальный код и проверку контракта, не только README.

Подтверждённые особенности, важные порталу:

| Особенность | Следствие |
|---|---|
| Общая лента использует `with_sent=bool(folder) or thread_id is not None` | По умолчанию отправленные скрыты. Для подтверждений КП нужен sent/folder/thread путь |
| `GET /messages/{id}/thread` возвращает has_more/next_cursor, но не принимает cursor в просмотренном обработчике | Не считать ответ полной цепочкой. Продолжение проверять через paginated feed с thread_id |
| `GET /messages/{id}` отдельно от `POST /messages/{id}/opened` | Интеграция читает GET, не вызывает opened: последний может поставить MARK_SEEN |
| AllowedAccounts применяется к письмам/цепочкам/вложениям | Сервисный доступ и локальные копии должны сохранять ограничения; нельзя просто открыть всю почту всем инженерам |
| Auth рассмотренных маршрутов основан на cookie | Не считать UI-session устойчивой machine-to-machine авторизацией; предусмотреть отдельный scoped read-only доступ |
| Внешние письма имеют body_html | Безопасный preview, внешние ресурсы/трекеры по умолчанию не загружаются |
| В данных есть пересказ/вердикт модели | Для требований использовать первичный body/вложения, пересказ отмечать как производный |

Предлагаемое ограниченное расширение MailHub (имена маршрутов — проект контракта, не существующие endpoints):

- machine identity только на чтение с allowlist ящиков и аудитом;
- стабильная выгрузка изменений по cursor, включая поздно импортированные старые письма и изменения вложений; sent_at не заменяет change cursor;
- поля Message-ID/In-Reply-To/References, UTC дат, участников, источника/папки и attachment hashes, если их нет в текущем ответе;
- полный paginated thread retrieval или явно описанное использование feed;
- явное направление/признак sent, доступ к исходному содержимому/EML в согласованном объёме;
- отсутствие mark-seen, move, draft, send side effects у read integration;
- возможность безопасно связать письмо с внешним tender ID либо хранить эту связь только в портале.

Не требовать переделки MailHub в многопользовательский портал КП. Его роли и почтовая видимость имеют собственный смысл. Не переиспользовать токен классификационного агента без доказанного нужного scope.

Минимальный live proof: прочитать разрешённую цепочку с исходящим ответом, всеми страницами и одним вложением; доказать, что флаги/папки не изменились; проверить отказ на недоступный ящик. Без этой проверки интеграция не VERIFIED_LIVE.

## 4. TenderHub

Документация архива описывает `X-API-Key`, scope `tenders:read`, `/api/v1/tenders/brief`, overview, positions, positions/with-costs, boq-items-full, детализацию одной позиции и цены предложений. Есть endpoints записи, но первому выпуску портала они не нужны.

Существенные поля: client_note, manual_volume/manual_note, quantities/coefficients, base/commercial totals, quote_link, категории строк, hierarchy и is_section. `positions` пагинируется; with-costs имеет 30-секундный кэш с документированным обходом. API нельзя интерпретировать по названиям полей без семантики.

Пользователь подтвердил, что расчёт автоматически закрывается по сроку и служит версией этапа. Проверить/добавить:

- stage ID, deadline, close status, closed_at;
- неизменяемый calculation revision ID и получение полного атомарного снимка по нему;
- поведение повторного открытия/исправления;
- lineage строк/позиций между этапами;
- полный состав коммерческих затрат, корректировок, скидок, курсов/НДС/округлений;
- источник итогового КП и reconciliation формулы;
- change event/webhook или надёжный polling contract.

Результат этапа 00: gap list против фактической OpenAPI, не обещание, что все поля уже доступны. Production API-ключ в чат не запрашивается; используется согласованный secret channel/env.

## 5. RDWeb

Пользователь определил RDWeb как основной, более мощный сервис распознавания. Доступен пример экспортного архива, не подтверждённый API.

В примере: PDF, Markdown, HTML, JSON; 77 записей страниц и 383 блока JSON, включая штампы. Markdown содержит 320 заголовков блоков. Это не автоматически пропуск: штампы и основной текст могут экспортироваться по-разному. Проверять схему, а не равенство этих счётчиков.

Есть page_index/page_label, координаты, rotation, block IDs и внешние crop URLs. В Markdown различаются исходный текст и созданные описания/summary/verification. Учитывать это при извлечении требований.

Для автоматизации нужны сведения: endpoint/auth; загрузка/лимиты; request/idempotency ID; job status/progress; partial/final; callbacks/polling; версия схемы; связи document hash/job; экспорт оригинала и crops; срок хранения; ошибки/повторы; стоимость повторной обработки, если применима. До получения API поддержать полноценный ручной/папочный импорт архива.

Внешний URL в документе не является разрешением загружать произвольный адрес. Оригинал локально — основа воспроизводимого preview.

## 7. Яндекс Диск / SMB

Нужны две точные корневые папки (тест и production), правила имён/прав, состав отправляемого и внутреннего, объём/квоты, service identity, способ проверки integrity. Портал не открывает публичные ссылки автоматически.

Яндекс Диск не путать с почтой Яндекс 360 или уже имеющимся Google Drive источником LocalAI. Это отдельный адаптер. Инструкции по auth/SDK сверять с актуальными официальными документами во время реализации.
