# Этап 05 — Собственный индекс и поиск по версиям

Продолжай проект «Контур КП». Прочитай docs/spec/01_PRODUCT_SPEC.md, актуальные ADR, docs/project-state.md, предыдущее независимое ревью и применимые инструкции репозитория. Если пакет находится в другом каталоге, найди его по именам файлов. Выполни только указанный ниже этап. Не начинай следующий. Все инварианты I01–I19 обязательны. Отчёт — по docs/spec/06_TRACKER_AND_TEMPLATES.md; проверки — с учётом docs/spec/05_ACCEPTANCE_CASES.md. Не объявляй fixture рабочей интеграцией. Передай точный проверяемый коммит независимому ревьюеру.

Этап переопределён решением D-013: Locus (LocalAI) закрывается, его поисковое ядро переносится в портал. Внешнего адаптера `LocalAiIndex` больше нет, X-04 и Q-13 закрыты как неприменимые. Решения D-013…D-021 приняты; архитектура уточнена ревью 05-pre-1 (`docs/reviews/05-pre-review-1.md`). Основной источник по индексу — ADR-012; модель данных — `docs/architecture/data-model.md` §4.13; состояния — `docs/architecture/state-machines.md` §20–21; API — `docs/contracts/portal-api.md` §2.4.

**Гейт до любой работы по поиску.** PostgreSQL не ниже 17 (ADR-002): `migrate` отказывает на меньшей версии. База создаётся в `packages/db/src/setup.ts` с `LOCALE_PROVIDER = builtin`, `BUILTIN_LOCALE = 'C.UTF-8'`; кластер разработки пересоздавать не нужно. Интеграционный тест создаёт базу штатным путём и проверяет `to_tsvector('russian','Договор') = to_tsvector('russian','договор')` и `lower('ДОГОВОР') = 'договор'`. Тестовые базы создаются тем же путём.

**Корпус и происхождение.** Корпус этапа — существующие прогоны распознавания RDWeb. Индексируются только фрагменты доказательного происхождения: `document_text` и `recognized_text`. `model_description` и `negotiation_hint` не индексируются ни одной веткой (`skipped`, `origin_not_evidence`) и не могут стать результатом или единственной цитатой (ADR-012 §21–22, I06). Каждый результат несёт `origin` и `matchedVia`. Договоры, письма и форматы вне охвата RDWeb приходят этапами 06a, 07 и 05a; не выдавай охват за полный и не реализуй договорной или почтовый домен.

**Индекс.** Версия индекса — сущность `search_index_version` (`building` → `active` → `retired`, `building` → `failed`) с неизменными параметрами: версия нарезки, конфигурация `russian`, шаблон входа модели, модель, отпечаток, размерность. Активация атомарна и только после полноты. Данные выведенной версии удаляет `index.purge` и только когда нет ожидающего прогона поиска на ней. Единица чанка — страница прогона; длинная страница режется с перекрытием, шапка (шифр, лист, наименование, тип, отметки, оси) повторяется в каждой части и получает вес `A`. Чанк связывается с фрагментами упорядоченно и со смещениями, цитата сводится к существующему `evidence_fragment.id`. Принадлежность чанка, связи и вектора единице источника и тендеру гарантируй составными внешними ключами: вставка фрагмента чужой единицы обязана падать на уровне БД.

**Векторы.** pgvector в той же PostgreSQL, `halfvec` без модификатора размерности, `SET STORAGE PLAIN`, узкая отдельная таблица с единицей и тендером для фильтра; размерность хранится явно, `CHECK (vector_dims(embedding) = dim)` и составной FK на версию; предел 4000. ANN-индекс не создаётся намеренно: с ним `WHERE` применился бы после обхода индекса. Причину запиши в комментарий миграции и закрепи тестом на `EXPLAIN`; возврат к HNSW — только по замерам (p95 векторной ветки выше 800 мс или устойчиво более 300 000 чанков). Кеш эмбеддингов ключуй по `text_sha256`, назначению, модели, отпечатку, шаблону входа и размерности. Векторы и кеш исключи из резервной копии по данным. `CREATE EXTENSION` выполняет административное подключение в `setup.ts`, миграция только проверяет наличие.

**Поиск — прогон `search_run`.** Три ветки: точный поиск обозначений, полнотекстовый `russian`, смысловой. Фильтр по `allowed_source_unit_ids` стоит в `WHERE` каждой ветки, до `ORDER BY … LIMIT`; постфильтрация top-k запрещена (A42). `POST /search` в одной транзакции разворачивает область и создаёт прогон, закрепляя контекст, запрос, `scope_hash`, набор единиц, версию индекса и ранжирования; точная и полнотекстовая ветки выполняются синхронно и отдаются с пометкой `preliminary`. Смысловая ветка: вектор запроса в кеше — синхронно; иначе задание `search.semantic` класса `gpu`; невозможна — прогон сразу `degraded` с причиной. Итоговый RRF (`k = 60`) пишется один раз при терминализации и только по зафиксированному набору веток; терминализация условна по `status = 'pending'`, срок — `deadline_at`, просрочка даёт `degraded`, позднее задание ничего не пишет. Терминальный прогон неизменен. `GET /search-runs/{id}` читает итог и заново проверяет права (`scope_changed`). Контекст — объединение по виду: реализуй `tender` (`working`, `review`, `release`), вид `contract` оставь зарезервированным без изменения модели прогона. Проверку ответа по БД портала сохрани второй линией.

**Очередь.** Индексация — пачки `index.build` (класс `default`) и `index.embed` (класс `gpu`), не более одной незавершённой пачки каждого вида на версию, следующая ставится в транзакции предыдущей с низким приоритетом. Приоритеты — по ADR-004 §7a. Заведи интерактивную полосу worker для `search.semantic`, чтобы смысловой запрос не ждал долгий импорт. Реранкер не заводится: переносится интерфейс шлюза и поведение при недоступности.

**Провайдер эмбеддингов.** Реализуй конкретный локальный провайдер за `ModelGatewayEmbeddings` — HTTP-клиент OpenAI-совместимого `/v1/embeddings` на loopback или в LAN — с конфигурацией, отпечатком модели (пробный вектор, косинус ≥ 0,999) и проверкой размерности до записи. Контрактные тесты — против поддельного HTTP-сервера. Конвейер, фильтр области и жизненный цикл прогона тестируй детерминированным поддельным провайдером. Машина разработки без GPU (U-08): живой прогон — `NOT_RUN`, статус провайдера не выше `VERIFIED_FIXTURE`. Без конкретного провайдера смысловая ветка в отчёте — `PARTIAL`, готовность к эксплуатации не заявляется.

**Регрессионный контракт Locus.** Веди `docs/architecture/locus-regression-manifest.md`: 9 случаев со статусом `stage05` — гейты этапа, 8 отложены с этапом и причиной. Заполни колонку «Тест портала». Пороги на итоге по ветвям `{exact, fts}`: утечка между тендерами равна нулю как жёсткий гейт, Recall@5 не ниже 0,85, MRR не ниже 0,70, точность цитаты равна единице. Точность текущей редакции измеряй RT-02.

Закрой R04-19: у фрагмента без страницы (`page_index IS NULL`) просмотр доказательства пишет «фрагмент не привязан к странице; откройте оригинал целиком», а не «Страница оригинала загружается…».

Проверки, только на корпусе RDWeb: гейт локали тестом создания базы; два тендера с одинаковой фразой — утечка ноль; две единицы источника одного тендера, из которых в области одна; два этапа с противоположными ответами; два прогона одного PDF — поздний первым при `limit = 1`, исторический режим поздний не видит; вставка фрагмента чужой единицы в связь чанка падает на уровне БД; план векторной ветки без индексного обхода; неполная версия не активируется; удаление выведенной версии ждёт ожидающий прогон; кеш другой модели не используется; вектор чужой размерности непредставим; `model_description` не находится; просроченный прогон — `degraded`, позднее задание его не перезаписывает; итог только по зафиксированному набору веток; повторное чтение после отзыва прав — `scope_changed`; новая индексация не ломает старую цитату; удаление индекса не уничтожает оригинал; отсутствие результатов не становится утверждением отсутствия требования; случаи манифеста `stage05`. Почтовые и договорные проверки — не на этом этапе (07, 16, 06a).

Выход: поиск на закреплённом комплекте с явным прогоном, точные источники, честный охват. Индекс — производные данные: его потеря не трогает доказательства и выпуски.
