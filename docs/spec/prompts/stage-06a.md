# Этап 06a — Договорной контур

Продолжай проект «Контур КП». Прочитай docs/spec/01_PRODUCT_SPEC.md, актуальные ADR, docs/project-state.md, предыдущее независимое ревью и применимые инструкции репозитория. Если пакет находится в другом каталоге, найди его по именам файлов. Выполни только указанный ниже этап. Не начинай следующий. Все инварианты I01–I19 обязательны. Отчёт — по docs/spec/06_TRACKER_AND_TEMPLATES.md; проверки — с учётом docs/spec/05_ACCEPTANCE_CASES.md. Не объявляй fixture рабочей интеграцией. Передай точный проверяемый коммит независимому ревьюеру.

Заведи `contract` рядом с `tender` — не надсущностью «проект» и не статусом «выигран» у тендера. Договор живёт годами после закрытия тендера и обрастает допсоглашениями; как статус тендера он переоткрывал бы готовность давно выпущенных этапов.

Доступ строится по образцу `mailbox_access`: общий внешний корпус и явная выдача, администратор ведёт строки. Возможности `contract.read`, `contract.write`, `admin.contract` — вторым типом рядом с возможностями тендера, вторая линия в БД обязательна.

Документы, редакции, прогоны распознавания и фрагменты получают необязательную принадлежность договору при обязательном ровно одном владельце — тендер или договор. Составные внешние ключи дублируются по договору. Это самая опасная миграция плана: ошибка даёт молчаливую утечку между тендером и договором, поэтому нужен отдельный регрессионный набор.

Связь договора с тендером подтверждает человек, и она не расширяет область поиска: единицы договора лишь предлагаются кандидатами в состав источников этапа, а ищутся только после явного включения в снимок. Поиск по действующему договору после закрытия тендера — вид контекста `contract` (ADR-012 §24): `contractId`, текущий корпус договора или его снимок, право `contract.read`. Добавь его расширением `CHECK` и колонкой владельца в `search_run`, не меняя статусов, результатов и API чтения прогона; связь договора с тендером не расширяет область ни в одну сторону.

Проверки: инженер без выданного доступа не видит договор ни списком, ни по прямому идентификатору, ни поиском в контексте `contract`; документ договора не попадает в поиск по тендеру без включения в снимок; документ тендера не попадает в поиск по договору; подтверждение связи не меняет исторический выпуск.

Выход: корпус действующих договоров внутри портала с правами и аудитом.
