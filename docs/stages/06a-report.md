## Результат для пользователя

В портале появился раздел «Договоры». Договор — самостоятельный объект рядом с тендером: номер, предмет, контрагент, дата; основной документ, допсоглашения и приложения со своими редакциями; распознавание PDF по экспорту RDWeb; поиск по текущему корпусу договора. Договор связывается с тендерами «многие ко многим»; связь подтверждает человек, и она ничего не открывает: документы договора лишь предлагаются кандидатами в состав этапа тендера. Доступ — только явной выдачей; администратор договоров ведёт выдачи, но содержимого не видит.

## Интерпретации — на подтверждение ревьюера

1. Создатель получает `contract.read` и `contract.manage`, но не `contract.link`: OD-2 выделяет подтверждение связи отдельным правом; при fail-closed оно выдаётся явно.
2. `admin.contract` сохранён только для ведения строк доступа (образец `mailbox_access`, D-017); D-022 уточнён этой формулировкой.
3. Выдача по договору действует при роли инженера или руководителя (как назначение на тендер): администратор без такой роли не выдаст себе чтение — отказ `409`.
4. `contract.manage` без `contract.read` меняет только номер и предмет и архивирует; контрагент и дата — содержательные поля.
5. Связь с тендером требует и `source.write` по тендеру: она предлагает кандидатов в состав этапов этого тендера.
6. Архив связи: рабочий состав этапа больше не ищет единицы этого договора (исключены правами), заморозка черновика с ними — `409 contract_link_archived`; исторические снимки воспроизводимы.
7. Распознавание редакции договора отправляет событие барьера только этапам, в последнюю ревизию состава которых человек её включил.
8. Происхождение (`document_occurrence`) для договора не пишется — таблица не менялась; имя файла при выдаче — название документа с расширением типа.
9. Журналы аудита договорных действий без содержательных полей (контрагент, имена файлов и документов — только признак изменения); события связи не попадают в журнал тендера участникам без выдачи.
