## Результат для пользователя

Инженер открывает вкладку «Требования» этапа. Руководитель создаёт реестр на зафиксированном снимке области. Модель по кнопке предлагает кандидатов — они помечены «Гипотеза модели» и ждут решения. Инженер проходит кандидатов по одному, правит предложения и предлагает свои; руководитель подтверждает или отклоняет. Подтверждённое требование получает код `R-0001` и неизменяемые ревизии; в карточке — основания с ролью, история оценок покрытия (позиции расчёта, комплексная расценка, решение, ручное подтверждение) и решения с заменой. Полнота считается по фрагментам снимка: связан с требованием, только с фактом, «не требование» или не просмотрен; завершить проход можно только без непросмотренных. Допущения ПД, вопросы заказчику и пометки этапа ведутся отдельно. Требование, противоречащее действующему (тот же параметр с другим значением на той же области) или с противоречащим основанием, помечено «Конфликт» и подтверждается только с пояснением; оценка покрытия, где единица требования не совпадает с единицей строки расчёта, помечена «Единица не совпадает с расчётом» и записывается как «покрыто» только с пояснением. Формулировка видна только тем, кто читает все её основания и всё, из чего она могла быть получена; остальным — оболочка без текста.

### R08-01 — неверная единица и конфликтующие требования

| Что | Поведение этапа 08 |
|---|---|
| единицы | единицы требования — из параметров ревизии; единица объекта расчёта — строки, у комплексной расценки — позиции; сравнение после нормализации записи (`unit_normalize`: регистр, пробелы, точки, `³` / `²`, `куб.м` → `м3`, `кв.м` → `м2`, `п.м` → `м`, `тн` → `т`); статус `match` / `mismatch` / `not_comparable` пишет БД в каждый объект расчёта, значения клиента не принимаются |
| покрытие при несовпадении | «покрыто» и «частично» — только с `unitMismatchReason`: без него API — 409 `unit_mismatch` с объектами и единицами, прямой SQL — 23514 на COMMIT; признак несовпадения — в оценке, в карточке и в реестре |
| конфликт | действующее требование того же реестра: тот же параметр (имя без регистра и лишних пробелов), другой ключ значения (после R08-03 — число каноническим `numeric`, иначе текст; единица — часть ключа; И-08-16), пересекающаяся область (пустое поле — весь объект; разные этажи не пересекаются); основание `contradicts` у кандидата — тоже конфликт |

### R08-02 — формальная политика видимости производного текста

T(o) = фрагменты оснований объекта `o` в любой роли ∪ T(каждого объекта, из которого текст `o` мог быть унаследован). Наследование: требование ← все ревизии и их кандидаты; кандидат ← правка, перенос, цель правки, требование прежнего реестра; факт и кандидат факта — так же; решение ← требование-предмет и заменённое решение; допущение ← все ревизии, связанное требование и заменённое допущение; вопрос ← связанное требование; оценка покрытия ← требование, фрагменты и решения — объекты оценки. Производные поля (формулировка, параметры, область, обоснование, значение, текст решения, допущения и вопроса, причина и объекты покрытия, пояснения, имя параметра конфликта) видны, только если пользователь по правам источника читает каждый фрагмент T(o). ### R08-03 — нормализация значения параметра конфликта

В 0020 ключ значения строился как текст без пробелов (`trim`, запятая → точка, удаление пробелов, `lower`): `100`, `100.0` и `100,00` считались разными и давали ложный конфликт, а `5 x 10` и `5x10` — равными. Миграция `0021` разделяет канонизацию (И-08-16):

| Значение | Правило | Примеры |
|---|---|---|
| сведение пробелов | пробелы, табуляция, перевод строки, U+00A0, U+2007, U+2009, U+202F → один пробел; края обрезаются | `1 000` → `1 000` |
| число | запись целиком: знак `+`/`-` (необязательно), цифры подряд или группы по три через пробел, дробная часть после одной точки или запятой (необязательно); ключ — `numeric` без незначащих нулей (`trim_scale`) | `100` = `100.0` = `100,00` = `+100`; `100` ≠ `100.1`; `1 000,50` = `1000.5` |
| текст | всё остальное: нижний регистр, пробелы внутри сведены к одному и не удаляются; запятая и точка не заменяются | `B30` = ` b30 `; `B30` ≠ `B30.0`; `5x10` ≠ `5 x 10`; `IP54`, `1e3`, `10 00`, `.5` — текст |
| единица | часть ключа после `unit_normalize`; пересчёта нет | `100 мм` ≠ `100 см`; `12 куб.м` = `12,0 м³` |

Файл 0020 не изменён: он применён в передаче R08-1, а мигратор отклоняет изменённую применённую миграцию (ADR-002; так же исправлялся R05a-01). - Модель в цикле: ложные цитаты и инструкции в документах отсекаются до записи, но качество предложений на живой модели не проверено.

- Текст значения сравнивается посимвольно после нормализации: одинаковые по виду латинская и кириллическая буквы (`B30` и `В30`) различаются и дают конфликт с пометкой; пересчёта единиц нет (И-08-16, И-08-17).
