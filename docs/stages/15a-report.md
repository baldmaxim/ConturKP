## Результат для пользователя

- Повтор запроса с тем же ключом идемпотентности после изменения прав пользователя больше не возвращает сохранённый ответ. Сервер отвечает `409` с понятным сообщением: команда уже выполнена, данные нужно перечитать. Второй раз команда не выполняется.
- Если права не менялись, повтор работает как раньше: тот же ответ, без второго выполнения.
- Отклонить гипотезу модели может только тот, кто читает её основания. Остальным — отказ; текст гипотезы они не получают.
- Экраны не менялись.

## Что найдено

Инвентаризация (проект §7, снята по коду до исправления): 79 объявлений `idempotent: true`, 82 маршрута.

| Класс | Маршрутов | Смысл |
|---|---|---|
| A | 31 | в ответе ID, статусы, счётчики или собственный ввод — отзыв права ничего не раскрывает |
| B | 21 | в ответе есть текст, зависящий от прав, но то же право проверяет `authorize` — повтор после отзыва получал отказ и раньше |
| C | 26 | в ответе есть такой текст, а право проверяет только `run` или представление — повтор после отзыва возвращал сохранённый текст |
| `replay` | 4 | исправлены на этапе 15, ответ строится заново |

Класс C: карточка комплекта (семь команд согласования и выпуска), диалог с ответами и цитатами, замечания и разногласия (семь команд), гипотеза модели, снимок источников, кандидаты и карточка требования (восемь команд), допущение. Поля и права — в проекте §7.

Исполняемое подтверждение дефекта на коде `9e57f44`: руководитель создаёт допущение по требованию, закрытому вместе с договором; доступ к договору отзывают; чтение формулировку уже скрывает, а повтор команды с тем же ключом возвращает `201` с полной формулировкой (`artifacts/stage-15a/regressions-15a-before.log`).

**S15a-01 — найдено инвентаризацией, вне повтора.** `POST /model-suggestions/{id}/reject` возвращал текст и обоснование гипотезы без проверки оснований: участник тендера без `mail.read` получал их в первом ответе и мог отклонить гипотезу, которую не читает. Подтверждено тем же журналом: `200` вместо отказа.

## Что сделано

| Что | Где |
|---|---|
| отпечаток прав пользователя: роли, назначения, выдачи по договорам и ящикам | `packages/db/src/access.ts` — `accessFingerprint` |
| сохранённый ответ хранит отпечаток; при повторе с другим отпечатком или без него — `409 replay_unavailable`, `run` не вызывается | `apps/server/src/http/command.ts` |
| отклонение гипотезы — только при читаемых основаниях, иначе `409 restricted_fragments` | `apps/server/src/routes/discrepancies.ts` |
| тесты | `tests/replayAccess.test.ts` (6), `tests/suggestionRejectAccess.test.ts` (3) |
| документы | проект с инвентаризацией; `portal-api.md` §1; `defects.md` (S15-14, S15a-01); `test-plan.md`; `requirements-traceability.md` (I13, I14) |

Миграций нет: отпечаток хранится в JSON записи идемпотентности. Маршруты, права и представления чтения не менялись, кроме отклонения гипотезы. Команды этапа 15 с `replay` не менялись.

Решения исполнителя (проект §3):
- **Защита в обёртке, а не по одной команде.** Она действует на все 78 команд без `replay` и на будущие: автор новой команды не может забыть её включить.
- **Отказ, а не ограниченное представление.** Обёртка не умеет строить представление каждой команды; чтение объекта уже делает это правильно. Review 15-1 допускает оба варианта.
- **Отказ при любом изменении прав, включая расширение.** Сравнение «права не уменьшились» сложнее и почти ничего не даёт: повтор нужен сразу после обрыва связи. Цена ложного отказа — одно перечитывание.
- **Записи без отпечатка (созданные до обновления) тело не отдают.** Срок жизни записи — 7 дней; после обновления установки повторы прежних команд получают отказ, а не старое тело.

## Непроверенное

- Windows: все прогоны — `NOT_RUN` у разработчика.
- Сквозной тест отзыва права сделан на одной команде класса C (`assumption.create`); для остальных 25 класс определён чтением кода.
- Отзыв `mail.read` сквозным сценарием на команде с текстом письма в ответе не проверялся: проверено, что изменение выдачи по ящику меняет отпечаток и закрывает сохранённый ответ.
- Закрытость, изменившаяся без изменения прав пользователя (к объекту добавили основание из закрытого для него источника): сохранённый ответ отдаётся, в нём только то, что пользователь уже получил законно. В объём аудита не входит (проект §3.5).
- Первые ответы команд (без повтора) на маску закрытого текста проверялись только чтением при инвентаризации; найден один дефект (S15a-01). Полного аудита первых ответов нет.
- Поведение клиента портала при `409 replay_unavailable`: показывается общее сообщение об ошибке; отдельного сценария интерфейса нет.
- Обновление установки: записи идемпотентности прежнего вида проверены тестом на вставленной записи, а не на копии рабочей базы.
