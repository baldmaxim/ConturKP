## Результат для пользователя

- **Профиль → «Доступ для чат-клиентов».** Пользователь выпускает токен для Codex или Cursor: название, клиент, срок (7, 30 или 90 дней), по желанию — право предлагать. Значение показывается один раз. В списке видно, какой токен действует, когда им пользовались в последний раз; любой можно отозвать. Действующих — не больше пяти.
- **Чат-клиент** подключается к порталу по адресу `<портал>/mcp` и работает с правами пользователя: выбирает тендер и этап, ищет по источникам с цитатами, читает требования, расчёт и экономику, замечания, вопросы, решения, готовность, сравнивает два выпуска.
- **Чат не выбирает тендер сам.** Без указанного тендера и этапа инструмент возвращает список доступных дел.
- **Чат может только предложить:** замечание, вопрос заказчику, текст условия, причину изменения.
- **Этап → «Предложения из чата».** Человек принимает или отклоняет предложение. Принятое замечание, вопрос или причина создаются от его имени; серьёзность замечания задаёт он.
- Согласования, выпуска, отправки, решений по удержаниям и рискам через чат нет.
- Журнал тендера показывает вызовы чат-клиента отдельно от действий человека.

## Решения владельца и толкования

- **D-037** (владелец, 2026-10-12): для живой проверки доступны Codex и Cursor на машине ревьюера; срок токена — 30 дней по умолчанию, выбор 7 / 30 / 90, не больше пяти действующих.
- Толкования исполнителя (проект §14, §16; не решения владельца):
  - предложения хранятся в `mcp_proposal`, а не в `model_suggestion` (S16-01);
  - добавлены `list_requirements` и `list_decisions`; `capture_calculation` не делается (S16-03, S16-04);
  - область выпуска для поиска — снимок источников его комплекта, без нового режима поиска (S16-05);
  - `propose_change_reason` относится к выводу сравнения выпусков этапа 15 (`comparisonId`, `itemId`);
  - принятие текста условия записи не создаёт;
  - числа: страница 20 (до 50), фрагмент до 2000 знаков, ответ до 64 КБ, 60 вызовов в минуту и 600 в час;
  - точка выключена по умолчанию; до этапа 17 проверяется на `localhost` (TLS — U-02);
  - отказ `out_of_scope` один и тот же для чужого и несуществующего объекта.

## Непроверенное

- Windows: все прогоны — `NOT_RUN` у разработчика.
- Codex и Cursor: ни один клиент не подключался. Не проверено, какую ревизию протокола шлёт каждый, как он показывает `needs_selection`, передаёт ли заголовок авторизации из переменной окружения так, как описано.
- Сеть и TLS: точка проверялась только на `localhost` по HTTP.
- Клиенты ревизий с рукопожатием проверены двумя сырыми запросами (`initialize`, `tools/list`), а не полным клиентом прежней версии SDK.
- Потоковые ответы (SSE) не используются и не проверялись.
- Лимит вызовов — в памяти одного процесса; при нескольких процессах `server` не действует общим счётом.
- Вырезание секретов — по известным шаблонам: секрет незнакомого вида не будет скрыт.
- Нагрузка: время инструментов на больших тендерах не измерялось; `list_requirements`, `list_findings`, `list_decisions` читают весь список и режут страницу в памяти.
- `list_decisions` не отдаёт решения по замечаниям; `list_documents` для этапа не отдаёт письма и протоколы как отдельные единицы — они видны в снимке выпуска.
- Блокеры боевого выпуска не менялись: готовность боевого комплекта через MCP проверена на данных фикстуры.

Область ревью: миграция 0040; `apps/server/src/mcp/`; `apps/server/src/routes/apiTokens.ts`, `mcpProposals.ts`; `packages/db/src/apiTokens.ts`, `mcpProposals.ts`; `apps/web/src/pages/mcp/`; тесты `mcp*.test.ts`; `docs/contracts/mcp-tools.md`; `docs/integrations/mcp-clients.md`.

Что проверить в первую очередь:
1. Обход прав через новый канал: каждый инструмент чтения — для не участника, участника без `mail.read`, участника без доступа к договору, после снятия с тендера; закрытые объекты должны приходить без текста.
2. Утечки в самой точке: значение токена в журналах, записях идемпотентности, ответах и ошибках; внутренние адреса и пути в ответах.
3. Предложения: повтор и гонка `requestId`, чужая и несуществующая цитата, решение человеком без права читать цитаты, повтор команды принятия после отзыва права.
4. Вторая линия 0040 ролью приложения.
5. Протокол: клиент актуальной ревизии и клиент с рукопожатием; методы, Origin, размер тела.
6. Живая проверка Codex и Cursor по `docs/integrations/mcp-clients.md` §4 — результат отдельно от проверки протокола.
7. На Windows: полный набор, typecheck, build, smoke, интерфейс 16, регрессия интерфейса 02–15.
